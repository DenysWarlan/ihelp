# ADR-001: Перехід на ручний розподіл клієнтів

## Контекст

Поточна система має автоматичний розподіл (`autoAssign`) зі scoring: спеціалізація +3, мова +2, доступність +1. Однак:
- Координатори та супервізори потребують контролю над призначенням
- Потрібно враховувати неформалізовані критерії: стать консультанта, специфіку запиту, досвід з подібними кейсами
- Автоматичний scoring не враховує gender preference клієнта
- Backend вже має endpoint `POST /assignment/:id/reassign` (ручне перепризначення) і `POST /assignment/:id/manual-assign` (ручне первинне)

## Варіанти

### Варіант A: Повне видалення auto-assign, тільки ручний розподіл
- **Плюси:** Повний контроль координатора, простота, відповідає запиту стейкхолдерів
- **Мінуси:** Більше навантаження на координатора, затримка при високому потоці

### Варіант B: Auto-assign як suggestion, координатор підтверджує
- **Плюси:** Зберігає автоматику як допоміжний інструмент, менше навантаження
- **Мінуси:** Складніший UX, потребує окремого UI для підтвердження

### Варіант C: Hybrid — auto-assign за замовчуванням, координатор може перевизначити
- **Плюси:** Працює для обох сценаріїв, backwards compatible
- **Мінуси:** Двозначність: хто відповідає? Координатор чи система?

## Рішення

**Варіант B: Auto-suggest + ручне підтвердження.**

Причини:
1. Scoring алгоритм вже реалізований — видаляти його нераціонально
2. Координатор отримує suggestion із рейтингом, але приймає фінальне рішення
3. Assignment page вже має UI для перегляду suggestions — потрібно додати кнопку "Призначити"
4. `autoAssign()` НЕ викликається автоматично при створенні кейсу (перевірено) — він тільки рахує score

### Додаткові зміни

#### Gender field у ConsultantProfile
- Додати `gender` поле до Prisma-моделі `ConsultantProfile` (`String?`, nullable)
- Значення: `'male' | 'female' | 'other' | null`
- Відображати в UI assignment для інформованого рішення координатора
- НЕ використовувати для автоматичного scoring — це рішення координатора

#### Зміни в Assignment UI
- Показувати suggestions з кнопкою "Призначити" замість автоматичного assignment
- Додати фільтри: спеціалізація, мова, стать
- Показувати workload (current/max cases)

## Наслідки

### Позитивні
- Координатор має повний контроль
- Scoring допомагає, але не замінює людське рішення
- Gender preference можна враховувати без дискримінаційної автоматики

### Негативні
- Кожен новий кейс потребує ручної дії координатора
- Можлива затримка при призначенні у нерабочий час

### Ризики
- Якщо координатор відсутній — кейси залишаються без призначення (mitigation: SLA alerts вже реалізовані)
- Gender field є sensitive data — потрібно враховувати GDPR compliance

## Реалізація

### Prisma migration
```prisma
// Додати до ConsultantProfile:
gender String? @map("gender")
```

### Backend
- `assignment.service.ts` — `autoAssign()` залишається як scoring helper
- Suggestions endpoint вже існує (`GET /assignment/suggestions/:caseId`)
- Manual assign endpoint вже існує (`POST /assignment/:id/manual-assign`)

### Frontend
- Assignment page: замість auto-assign, показувати список з кнопкою "Призначити"
- Додати gender badge в suggestion cards
- Координатор/супервізор бачать повний контекст перед рішенням
