# ADR-002: Архітектура чатів — Staff Chat vs Case Detail Chat

## Контекст

Існують два інтерфейси чату для консультанта:

1. **Staff Chat** (`/staff/chat`) — повноцінний чат через `/api/chat/staff/conversations`
   - Список усіх розмов консультанта
   - Підтримка статусів повідомлень (sent/read)
   - Окремий UI з conversation list + message panel
   
2. **Case Detail Chat** (`/staff/cases/:id`) — вбудований в сторінку кейсу через `/api/cases/:id/messages`
   - Контекст кейсу (sidebar з деталями, нотатки, SLA)
   - Простіший UI — тільки повідомлення + input

Обидва пишуть у одну й ту саму conversation (backend зв'язує `CareCase` ↔ `ClarificationSession`). Повідомлення відправлені з одного інтерфейсу видимі в іншому.

## Варіанти

### Варіант A: Об'єднати в один інтерфейс
- **Плюси:** Немає плутанини, один source of truth
- **Мінуси:** Втрата контексту кейсу при спілкуванні; або перевантажений UI з sidebar+chat

### Варіант B: Зберегти обидва, чітко визначити призначення
- **Плюси:** Кожен UI оптимізований для своєї задачі; не потрібно редизайну
- **Мінуси:** Потрібно чітко пояснити користувачу різницю

### Варіант C: Case Detail як primary, Staff Chat тільки для огляду
- **Плюси:** Case-centric workflow (кожне повідомлення в контексті кейсу)
- **Мінуси:** Незручно переглядати всі розмови одночасно

## Рішення

**Варіант B: Зберегти обидва інтерфейси з чітким розмежуванням.**

### Призначення кожного чату:

| Інтерфейс | Призначення | Коли використовувати |
|-----------|-------------|---------------------|
| **Staff Chat** (`/staff/chat`) | Центр комунікацій | Огляд усіх розмов, швидка відповідь, перегляд непрочитаних |
| **Case Detail** (`/staff/cases/:id`) | Робота з кейсом | Спілкування в контексті конкретного кейсу з доступом до деталей, нотаток, SLA |

### Синхронізація

Обидва інтерфейси вже синхронізовані на рівні бекенду — вони працюють з одними й тими самими повідомленнями в одній conversation. Немає потреби в додатковій синхронізації.

**Що потрібно зробити:**
1. Додати tooltip/help text в UI, що пояснює призначення кожного чату
2. У Staff Chat — додати link "Відкрити кейс" → перехід до `/staff/cases/:id`
3. У Case Detail — додати link "Відкрити повний чат" → перехід до `/staff/chat` з вибраною розмовою

## Наслідки

### Позитивні
- Не потрібен рефакторинг існуючої архітектури
- Кожен інтерфейс оптимізований для свого use case
- Backend вже забезпечує consistency

### Негативні
- Користувачі потребують пояснення (onboarding tooltip)

### Ризики
- Якщо в майбутньому додаються group chats або channel-based messages — потрібно переглянути цей ADR
