# S-E11-06: Near real-time оновлення даних

## Контекст
Дашборди з застарілими даними можуть призвести до хибних рішень. Затримка не більше 15 хвилин забезпечує достатню актуальність для оперативного управління, при цьому дозволяючи використовувати оптимізації (materialized views, pre-aggregation) для продуктивності. Кнопка примусового оновлення дає можливість отримати найсвіжіші дані в критичних ситуаціях.

## User Story
Як супервiзор, я хочу бачити актуальнi данi на дашбордi з мiнiмальною затримкою, щоб приймати рiшення на основi поточної ситуацiї.

## Критерiї приймання
- [ ] AC1: Данi на дашбордах оновлюються з затримкою не бiльше 15 хвилин
- [ ] AC2: На дашбордi вiдображається час останнього оновлення даних
- [ ] AC3: Є можливiсть примусового оновлення даних (кнопка "Оновити")

## Технiчнi нотатки
- Розглянути materialized views або pre-aggregated таблицi для забезпечення продуктивностi
- Фонова задача (cron/queue) для перiодичного перерахунку метрик

## Залежностi
- S-E11-01, S-E11-04 — дашборди, що потребують оновлення
