# S-E06-02: Атомарність призначення (race condition protection)

## Контекст
При одночасному створенні кількох кейсів може виникнути ситуація, коли двом кейсам призначається один консультант, у якого залишився лише один вільний слот. PostgreSQL CHECK constraint на рівні БД гарантує, що навантаження ніколи не перевищить ліміт, навіть при конкурентних транзакціях. Кейс, який не отримав консультанта, обробляється через fallback.

## User Story
Як система, я хочу атомарно зменшувати кількість вільних слотів консультанта при призначенні, щоб запобігти перевищенню ліміту при одночасних призначеннях.

## Критерії приймання
- [x] AC1: Atomic decrement вільних слотів з PostgreSQL CHECK constraint (current_cases < max_cases)
- [x] AC2: При одночасному призначенні останнього слота двом кейсам — один отримує консультанта, інший потрапляє у fallback
- [x] AC3: Constraint violation не призводить до помилки для Person — кейс обробляється через fallback

## Технічні нотатки
- PRD: ASSIGN-1
- PostgreSQL CHECK constraint + transaction isolation

- S-E06-03: Fallback на координатора (обробка при constraint violation)
