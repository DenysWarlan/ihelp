# S-E06-08: Повторний автопідбір при зміні доступності

## Контекст
Event-driven повторний підбір мінімізує час очікування Person — щойно з'являється вільний консультант, система автоматично перевіряє чергу непризначених кейсів. Це критично для ефективності платформи: без реактивного підбору кейси б чекали в черзі до наступного ручного втручання координатора або до cron job.

## User Story
Як система, я хочу повторно запускати алгоритм розподілу для кейсів у черзі, коли з'являється вільний консультант, щоб мінімізувати час очікування Person.

## Критерії приймання
- [x] AC1: При завершенні кейсу консультантом (вивільнення слота) система перевіряє чергу непризначених кейсів
- [x] AC2: При зміні статусу консультанта на "доступний" (повернення з відпустки) — перевірка черги
- [x] AC3: Кейси з черги призначаються в порядку FIFO з урахуванням алгоритму пріоритизації

## Технічні нотатки
- Event-driven: слухати події завершення кейсів та зміни статусу консультантів
