# S-E01-08: MFA для Staff

## Контекст
Staff-користувачі мають доступ до конфіденційних даних підопічних — компрометація їхнього акаунту несе значно більші ризики, ніж компрометація акаунту Person. Двофакторна автентифікація є стандартом для систем, що обробляють медичні та психологічні дані. Процедура відновлення при втраті MFA-пристрою має бути суворою, але досяжною.

## User Story
Як консультант/супервізор/координатор, я хочу захистити свій акаунт двофакторною автентифікацією, щоб запобігти несанкціонованому доступу до конфіденційних даних підопічних.

## Критерії приймання
- [ ] AC1: MFA активується для Staff при першому вході (TOTP)
- [ ] AC2: При активації MFA видаються 8 одноразових backup-кодів
- [ ] AC3: При втраті MFA-пристрою — вхід через backup-код
- [ ] AC4: При вичерпанні backup-кодів — відновлення через Admin (відеодзвінок, перевірка документа, підтвердження другим адміном/супервізором)
- [ ] AC5: Результат верифікації логується в audit log

## Технічні нотатки
- PRD: AUTH-9
- TOTP (RFC 6238) через otplib або аналог
- Backup-коди зберігаються хешованими

## Залежності

- S-E01-05: Рольова модель (MFA тільки для Staff-ролей)
