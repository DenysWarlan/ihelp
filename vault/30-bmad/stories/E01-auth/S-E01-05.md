# S-E01-05: Рольова модель та Guards

## Контекст
Платформа обробляє конфіденційні дані людей у вразливому стані — розмежування доступу за ролями є обов'язковою вимогою як для безпеки, так і для GDPR-відповідності. Guards забезпечують, що Person не має доступу до приватних нотаток консультанта, а консультант — до адміністративних функцій. Ця історія впливає на всі API-ендпоінти в системі.

## User Story
Як адміністратор платформи, я хочу щоб доступ до API обмежувався ролями, щоб кожен користувач мав доступ тільки до дозволених функцій.

## Критерії приймання
- [ ] AC1: Система підтримує 5 ролей: Person, Consultant, Supervisor, Coordinator, Admin
- [ ] AC2: NestJS Guards блокують доступ до ендпоінтів за роллю — 401 для неавторизованих, 403 для недостатніх прав
- [ ] AC3: Декоратор @Roles() дозволяє гнучко налаштовувати доступ на рівні контролера/ендпоінту
- [ ] AC4: Guards перевіряють JWT-токен і роль на кожному захищеному запиті

## Технічні нотатки
- PRD: AUTH-2, AUTH-3
- Реалізація через NestJS Custom Guards + @SetMetadata

## Залежності
- S-E01-04: JWT токени (Guards залежать від JWT payload з роллю)
