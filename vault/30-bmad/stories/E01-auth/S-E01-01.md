# S-E01-01: OAuth-автентифікація Person

## Контекст
Це базова точка входу для людей на платформу — без OAuth-автентифікації жодна інша функціональність не доступна. Підтримка кількох провайдерів (Google, Facebook, Telegram) критична для доступності, оскільки цільова аудиторія може мати обмежений набір акаунтів. Ця історія є фундаментом для всіх інших історій в E01 Auth та для всього потоку створення кейсів (E02).

## User Story
Як людина (Person), я хочу увійти через Google, Facebook або Telegram, щоб швидко отримати доступ до платформи без окремої реєстрації.

## Критерії приймання
- [ ] AC1: Person може увійти через Google OAuth 2.0 і отримує JWT (access + refresh)
- [ ] AC2: Person може увійти через Facebook OAuth 2.0 і отримує JWT
- [ ] AC3: Person може увійти через Telegram Login Widget і отримує JWT
- [ ] AC4: При помилці OAuth-провайдера (timeout, відмова токена) відображається повідомлення з можливістю повторити

## Технічні нотатки
- PRD: AUTH-4, AUTH-4a, AUTH-4b
- Кожен провайдер реалізується як окрема NestJS Strategy (Passport)
- Callback URL має бути конфігурованим через env

## Залежності
- Немає зовнішніх залежностей — це базова історія епіку
