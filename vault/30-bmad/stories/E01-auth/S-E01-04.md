# S-E01-04: JWT токени з rotation та crisis session

## Контекст
Безпека токенів критична для платформи, що працює з чутливими персональними даними. Token rotation захищає від викрадення сесій, а crisis session гарантує, що людина в кризовому стані не втратить доступ посеред важливої розмови через технічні причини. Ця історія забезпечує баланс між безпекою та безперервністю сервісу.

## User Story
Як авторизований користувач, я хочу мати безпечну та безперервну сесію, щоб не втрачати доступ під час роботи і бути захищеним від викрадення токенів.

## Критерії приймання
- [x] AC1: При кожному refresh видається новий refresh token, попередній інвалідується
- [x] AC2: При replay attack (використання інвалідованого refresh token) — вся token family відкликається (forced logout на всіх пристроях)
- [x] AC3: Кризова сесія не переривається forced logout протягом 24 годин
- [ ] AC4: Після 24 годин кризової сесії — продовження тільки з затвердженням супервізора; логується в audit log
- [ ] AC5: Silent token refresh під час активного upload — користувач не втрачає прогрес завантаження

## Технічні нотатки
- PRD: AUTH-1, AUTH-8, AUTH-8a
- Token family tracking в Redis
- Crisis session flag в JWT payload або Redis
