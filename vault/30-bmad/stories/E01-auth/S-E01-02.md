# S-E01-02: Implicit registration та єдиний акаунт

## Контекст
Людина в кризовій ситуації не повинна проходити додаткові кроки реєстрації — система має створити акаунт непомітно при першому контакті. Це знижує бар'єр входу та запобігає дублікатам акаунтів при одночасних зверненнях через різні канали. Пов'язана з S-E01-01 (OAuth) та S-E01-03 (зв'язування провайдерів).

## User Story
Як людина, я хочу автоматично отримати акаунт при першому вході або відправці анкети, щоб не проходити окрему реєстрацію.

## Критерії приймання
- [x] AC1: При першому вході через будь-який OAuth-провайдер автоматично створюється акаунт Person
- [x] AC2: При відправці анкети звернення без існуючого акаунту — акаунт створюється atomic upsert з unique constraint на контактне поле
- [x] AC3: Telegram-користувач без username отримує акаунт за chat_id
- [x] AC4: При одночасній відправці двох анкет — друга отримує існуючий акаунт (race condition handled)
- [x] AC5: При пізнішому вході через канал, використаний в анкеті — система знаходить існуючий акаунт

## Технічні нотатки
- PRD: AUTH-4c, AUTH-4e
- Atomic upsert з unique constraint для запобігання дублікатів
- chat_id як fallback ідентифікатор для Telegram без username

## Залежності
- S-E01-01: OAuth-автентифікація (механізм входу)
