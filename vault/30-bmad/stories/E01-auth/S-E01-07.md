# S-E01-07: GDPR-згоди

## Контекст
Платформа обробляє чутливі персональні дані (Art.9 GDPR — дані про здоров'я, психологічний стан), тому отримання явної згоди є юридичною необхідністю. Без згоди система не може створити кейс — це блокуюча залежність для E02 Cases. Відкликання згоди під час кризового кейсу потребує особливої обробки для захисту безпеки людини.

## User Story
Як людина, я хочу надати явну згоду на обробку моїх даних, щоб мої права були захищені відповідно до GDPR.

## Критерії приймання
- [ ] AC1: При першому вході/анкеті відображаються два чекбокси: загальна згода та згода Art.9 (чутливі дані)
- [ ] AC2: Timestamps обох згод зберігаються окремо в БД
- [ ] AC3: Без надання згоди кейс не створюється
- [ ] AC4: При відкликанні згоди Art.9 під час активного не-кризового кейсу — чутливі поля анонімізуються; консультант отримує сповіщення
- [ ] AC5: При кризовому кейсі відкликання відкладається (safety override)

## Технічні нотатки
- PRD: AUTH-7
- Поля: dataConsentAt, sensitiveDataConsentAt
- Перевірка dataConsentAt NOT NULL перед створенням кейсу

## Залежності
- S-E01-01: OAuth-автентифікація (згода збирається при першому вході)
- E02 Cases: створення кейсу заблоковане без згоди
- E12 GDPR: повна реалізація GDPR-прав
