# S-E02-08: Автоматична пауза при неактивності

## Контекст
Консультанти працюють з обмеженою кількістю слотів — кейси без активності мають автоматично переходити на паузу, щоб звільнити увагу для активних звернень. При цьому важливо коректно обробляти race condition, коли повідомлення від людини приходить одночасно зі спрацюванням auto-pause. Ця історія пов'язана з E09 Workload та E07 SLA.

## User Story
Як платформа, я хочу автоматично переводити кейс на паузу після 7 днів неактивності, щоб консультанти фокусувались на активних зверненнях.

## Критерії приймання
- [x] AC1: Якщо в кейсі немає активності > 7 днів — статус автоматично змінюється на on_hold
- [ ] AC2: Людина отримує повідомлення про паузу через активний канал
- [x] AC3: Auto-pause виконується через atomic status transition з optimistic lock
- [x] AC4: Якщо вхідне повідомлення має timestamp < timestamp спрацювання auto-pause — auto-pause скасовується, кейс залишається in_progress

## Технічні нотатки
- PRD: CASE-7 (v1.1)
- Cron job або Bull queue для перевірки неактивності
- Race condition handling: EDGE-23
