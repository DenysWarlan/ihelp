# S-E02-07: Optimistic locking

## Контекст
Кілька Staff-користувачів можуть одночасно працювати з одним кейсом — консультант оновлює нотатки, координатор змінює призначення, супервізор переглядає статус. Optimistic locking запобігає тихому перезапису даних, зберігаючи при цьому високу продуктивність (без блокування рядків у БД). Це особливо важливо для кризових кейсів з інтенсивною взаємодією.

## User Story
Як консультант, я хочу отримати попередження при одночасному редагуванні кейсу іншим користувачем, щоб не перезаписати чужі зміни.

## Критерії приймання
- [ ] AC1: Модель CareCase має поле version (integer, auto-increment при кожному update)
- [ ] AC2: При оновленні клієнт надсилає поточну version; якщо version не збігається — 409 Conflict
- [ ] AC3: Відповідь 409 містить повідомлення "Кейс було змінено іншим користувачем" з пропозицією перезавантажити
- [ ] AC4: Successful update повертає нову version

## Технічні нотатки
- PRD: CASE-10
- Prisma @updatedAt + custom version field
- WHERE id = :id AND version = :expectedVersion
