# S-E02-06: Audit log дій по кейсу

## Контекст
Повна аудиторська стежка необхідна для контролю якості роботи консультантів, розслідування інцидентів та GDPR-відповідності. Append-only структура гарантує цілісність записів — жодна дія не може бути видалена або змінена заднім числом. Це основа для звітності супервізорів та координаторів.

## User Story
Як супервізор/координатор, я хочу бачити повну історію дій по кейсу, щоб розуміти хронологію подій і контролювати якість роботи.

## Критерії приймання
- [x] AC1: Кожна зміна статусу кейсу логується (хто, коли, з якого статусу на який)
- [x] AC2: Кожне призначення/перепризначення консультанта логується
- [ ] AC3: Кожен перегляд кейсу Staff-користувачем логується
- [x] AC4: Audit log доступний тільки для ролей Supervisor, Coordinator, Admin
- [x] AC5: Записи в audit log незмінні (append-only)

## Технічні нотатки
- PRD: CASE-5
- Модель: CaseAuditLog (caseId, actorId, action, details JSONB, createdAt)
- Append-only: ніяких UPDATE/DELETE на таблиці audit log

- E01 Auth: S-E01-05 (рольова модель для обмеження доступу до логів)
