# S-E09-06: Конфiгурацiя лiмiтiв адмiном

## Контекст
Оптимальне навантаження на консультанта залежить від розміру команди, складності кейсів та поточної ситуації. Адміністратор повинен мати можливість гнучко змінювати ліміти без залучення розробників. Важливо, що зміна лімітів не впливає на вже призначені кейси — тільки на нові призначення. Валідація гарантує, що кризовий ліміт не перевищить загальний.

## User Story
Як адмiнiстратор, я хочу змiнювати лiмiти загальних та кризових кейсiв, щоб адаптувати систему до змiн у кiлькостi консультантiв та навантаженнi.

## Критерiї приймання
- [ ] AC1: Адмiн може змiнити глобальний лiмiт загальних кейсiв (default 10)
- [ ] AC2: Адмiн може змiнити глобальний лiмiт кризових кейсiв (default 3)
- [ ] AC3: Змiни набувають чинностi негайно для нових призначень
- [ ] AC4: Якщо консультант вже перевищує новий лiмiт — iснуючi кейси зберiгаються, новi не призначаються

## Технiчнi нотатки
- UI конфiгурацiї — частина E13 (Admin Panel)
- Валiдацiя: кризовий лiмiт <= загальний лiмiт

## Залежностi
- E13 (Admin Panel) — UI для змiни налаштувань
- S-E09-01 — загальний лiмiт, що конфiгурується
- S-E09-02 — кризовий лiмiт, що конфiгурується
