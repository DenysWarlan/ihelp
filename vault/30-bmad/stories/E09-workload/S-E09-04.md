# S-E09-04: Out-of-band ескалацiя при forced logout координатора

## Контекст
Якщо координатор перебуває у стані forced logout (AUTH-8), in-app push-сповіщення не буде доставлено. Без out-of-band каналів (SMS, email, phone) критичний алерт про вичерпання кризових слотів залишиться непоміченим. Ця сторі забезпечує надійну доставку ескалації за будь-яких обставин, використовуючи спільну інфраструктуру fallback chain з E08 (Crisis Protocol).

## User Story
Як супервiзор, я хочу щоб при overflow кризових слотiв ескалацiя вiдправлялась через SMS/email/phone навiть якщо координатор у станi forced logout, щоб кризовий кейс не залишився без ескалацiї через стан автентифiкацiї.

## Критерiї приймання
- [ ] AC1: При BURN-2 overflow ескалацiя використовує out-of-band канали: SMS, email, phone call
- [ ] AC2: In-app push вiдправляється додатково, але НЕ як єдиний канал
- [ ] AC3: При forced logout координатора (AUTH-8) — SMS/email доставляються незалежно вiд стану сесiї
- [ ] AC4: Fallback chain аналогiчний CRISIS-3: SMS → push → email → phone call

## Технiчнi нотатки
- Спiльна iнфраструктура fallback chain з E08 (Crisis Protocol)
