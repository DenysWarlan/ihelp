# S-E14-05: Форма звернення (Intake)

## Контекст
Форма звернення є найважливішим елементом для людей, які потребують допомоги. Вона збирає контактну інформацію та опис ситуації для створення Care Case. Форма має два рівні GDPR-згоди: базова (обов'язкова) та згода на обробку чутливих даних (Art.9, необов'язкова). При відмові від Art.9 кейс ескалюється координатору вручну.

## User Story
Як людина, що потребує допомоги, я хочу заповнити анкету зі своєю ситуацією, щоб мені призначили відповідного консультанта.

## Критерії приймання
- [ ] AC1: Сторінка `/request` містить поля: ім'я, країна, мова, спосіб зв'язку (email / Telegram / Facebook), тема (вибір із списку + "інше"), опис ситуації (необов'язкове textarea)
- [ ] AC2: Два GDPR-чекбокси: (1) згода на обробку персональних даних, (2) згода на обробку чутливих даних (Art.9)
- [ ] AC3: Форма не відправляється без чекбоксу (1); якщо (2) не відмічений — Care Case створюється без теми/опису, з попередженням користувачу
- [ ] AC4: Валідація формату email з real-time feedback; при невалідному email форма не відправляється
- [ ] AC5: Після відправки створюється Care Case зі статусом "нове" (API E02)

## Технічні нотатки
- При відмові від Art.9 — кейс ескалюється координатору для ручного призначення
- Автоматичне створення акаунту Person за контактним полем (AUTH-4e)
