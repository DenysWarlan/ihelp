# S-E14-04: Модальне вікно авторизації (Course Start)

## Контекст
Це модальне вікно є основним механізмом реєстрації нових користувачів через курси. Воно реалізує двофазну логіку: спочатку згода GDPR, потім OAuth-авторизація. У разі помилки OAuth виконується rollback згоди, що забезпечує цілісність даних. Це критично для GDPR-compliance платформи (AUTH-7).

## User Story
Як відвідувач, я хочу створити акаунт через зручний OAuth-провайдер і надати згоду на обробку даних, щоб розпочати проходження курсу.

## Критерії приймання
- [ ] AC1: Модальне вікно містить: заголовок, опис, чекбокс згоди на обробку даних, три OAuth-кнопки (Google / Facebook / Telegram), кнопку "Скасувати"
- [ ] AC2: OAuth-кнопки неактивні, поки чекбокс згоди не відмічений
- [ ] AC3: Після успішного OAuth — створюється enrollment і користувач переходить до першого уроку курсу
- [ ] AC4: При помилці OAuth після надання згоди — rollback: дані згоди видаляються, enrollment не створюється; користувач бачить повідомлення про помилку
- [ ] AC5: Timestamp згоди зберігається відповідно до AUTH-7

## Технічні нотатки
- Згода зберігається тільки після успішного OAuth (двофазна логіка)
- Залежність: E01 (Auth — OAuth flow, consent storage)
