# S-E03-03: Unified Message Bus та єдина модель повідомлення

## Контекст
Єдина модель повідомлення — архітектурна основа omnichannel-підходу. Без неї кожен канал мав би окрему таблицю, що ускладнює пошук, аналітику та роботу консультанта. Санітизація контенту (XSS protection) обов'язкова, оскільки повідомлення з месенджерів можуть містити шкідливий контент, який відображатиметься у веб-інтерфейсі консультанта.

## User Story
Як розробник платформи, я хочу мати єдину модель повідомлення для всіх каналів, щоб забезпечити однаковий досвід для консультантів незалежно від каналу комунікації.

## Критерії приймання
- [x] AC1: Модель Message містить: id, careCaseId, senderId, senderRole, channel, channelChatId, content, attachments, createdAt
- [x] AC2: Enum channel містить значення: web, telegram, instagram, facebook, viber (MVP валідація — тільки web, telegram)
- [x] AC3: Повідомлення з непідтримуваного каналу повертає 422 з повідомленням "Канал [X] ще не підтримується"
- [x] AC4: Всі повідомлення з будь-якого каналу зберігаються в єдиній таблиці Message
- [x] AC5: XSS-контент санітизується перед збереженням (DOMPurify, strip ALL HTML)

## Технічні нотатки
- PRD: CHAT-3, CHAT-4
- Prisma enum для channel
- Санітизація на рівні сервісу перед persist
