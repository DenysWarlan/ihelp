# S-E03-07: Ordering та дедуплікація webhook-повідомлень

## Контекст
Webhook-повідомлення від Telegram та інших месенджерів можуть приходити не в порядку відправки, а також дублюватися при retry. Неправильний порядок повідомлень може спотворити контекст розмови для консультанта, а дублікати — створити плутанину. Idempotent processing гарантує стабільність при мережевих проблемах.

## User Story
Як платформа, я хочу коректно сортувати та дедуплікувати вхідні повідомлення з месенджерів, щоб консультант бачив повідомлення у правильному порядку без дублікатів.

## Критерії приймання
- [x] AC1: Повідомлення сортуються за оригінальним timestamp, а не за часом отримання webhook
- [x] AC2: Дедуплікація по message_id — повторні webhook з тим самим message_id ігноруються
- [x] AC3: При затримці webhook — повідомлення вставляється в правильну хронологічну позицію
- [x] AC4: Idempotent processing: повторна обробка того ж webhook не створює побічних ефектів

## Технічні нотатки

- Unique constraint на (channel, channelMessageId)
- Ordering по originalTimestamp, fallback на createdAt
