# S-E17-09: Structured Logging та Correlation ID

## Контекст
Структуровані JSON-логи з correlation ID є необхідними для діагностики проблем у розподіленій системі. Correlation ID пробрасується через всі шари (middleware -> service -> repository), що дозволяє трейсити повний шлях запиту. Pino обрано за швидкість у production, а формат JSON забезпечує інтеграцію з системами аналізу логів.

## User Story
Як розробник, я хочу мати структуровані JSON-логи з correlation ID, щоб ефективно відстежувати запити та діагностувати проблеми.

## Критерії приймання
- [ ] AC1: Всі логи у форматі structured JSON (pino або winston)
- [ ] AC2: Кожен HTTP-запит отримує унікальний correlation ID (UUID)
- [ ] AC3: Correlation ID пробрасується через всі сервіси (middleware -> service -> repository)
- [ ] AC4: Логи включають: timestamp, level, correlation_id, module, message

## Технічні нотатки
- NestJS middleware для генерації/прокидання correlation ID з header `X-Correlation-ID`
- Pino рекомендований для production (швидкість)
