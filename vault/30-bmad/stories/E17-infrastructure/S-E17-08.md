# S-E17-08: CI/CD Pipeline

## Контекст
Автоматизований CI/CD pipeline забезпечує якість коду та безперервну доставку на staging. Обов'язкові PR checks (lint + tests) запобігають потраплянню дефектного коду в main. Автоматичний deploy на staging при push у main скорочує цикл зворотного зв'язку та дозволяє команді швидко перевіряти зміни.

## User Story
Як розробник, я хочу мати автоматизований CI/CD pipeline, щоб кожен push у main проходив перевірки та деплоївся на staging.

## Критерії приймання
- [x] AC1: Pipeline: lint -> unit tests -> build -> Docker image push -> deploy to staging
- [x] AC2: PR checks: lint + tests обов'язкові для merge
- [x] AC3: Docker images тегуються: `latest` + git SHA
- [x] AC4: Deploy на staging автоматичний при push у main

## Технічні нотатки
- GitHub Actions або GitLab CI (залежно від репозиторію)
- Secrets інжектяться через CI/CD variables (не в коді)
