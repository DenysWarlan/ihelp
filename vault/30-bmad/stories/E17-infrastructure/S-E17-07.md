# S-E17-07: Nginx Reverse Proxy

## Контекст
Nginx виконує роль єдиної точки входу для всього трафіку платформи, маршрутизуючи запити між frontend та backend. Підтримка WebSocket upgrade для Socket.io є критичною для real-time чату (S-E15-03). TLS та gzip compression забезпечують безпеку та performance у staging/prod середовищах.

## User Story
Як розробник, я хочу налаштувати Nginx як reverse proxy, щоб маршрутизувати трафік між frontend і backend та підтримувати WebSocket.

## Критерії приймання
- [x] AC1: Routing: `/api/*` -> backend (NestJS), `/` -> frontend (Angular static)
- [x] AC2: WebSocket upgrade для Socket.io (`/socket.io/`)
- [x] AC3: TLS: self-signed для dev, Let's Encrypt для staging/prod
- [x] AC4: Gzip compression для статичних ресурсів

## Технічні нотатки
- Nginx config як template з environment variables
- Staging/prod: certbot для автоматичного оновлення сертифікатів
