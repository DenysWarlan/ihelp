# S-E17-10: Rate Limiting та безпека

## Контекст
Rate limiting та базові механізми безпеки захищають API від зловживань та атак. Auth endpoints мають жорсткіший ліміт (5 запитів / 15 хвилин) для запобігання brute-force. TLS 1.3, Helmet та CORS забезпечують baseline security. Redis як storage для rate limit підтримує горизонтальне масштабування backend.

## User Story
Як розробник, я хочу налаштувати rate limiting та базові механізми безпеки, щоб захистити API від зловживань.

## Критерії приймання
- [ ] AC1: Глобальний rate limit на API (configurable)
- [ ] AC2: Auth endpoints: 5 запитів / 15 хвилин (тільки password-based; OAuth failures не враховуються)
- [ ] AC3: TLS 1.3 для всіх з'єднань (staging/prod)
- [ ] AC4: Helmet middleware для HTTP security headers
- [ ] AC5: CORS налаштований для дозволених origins

## Технічні нотатки
- `@nestjs/throttler` для rate limiting
- Rate limit storage: Redis (для підтримки кількох інстансів)
