# S-E04-17: Екран управління файлами

## Контекст
Немає UI для перегляду, пошуку та управління завантаженими файлами. Admin не може бачити що зберігається, знаходити orphaned файли або очищати сховище.

## User Story
Як Admin, я хочу мати екран управління файлами для перегляду, пошуку та видалення завантажених файлів.

## Критерії приймання
- [ ] AC1: Новий route `/staff/files` з навігацією в sidebar (іконка Folder, під Courses)
- [ ] AC2: Grid/List view з thumbnails (images) або type icons (PDF, video)
- [ ] AC3: Кожен файл показує: key, size, upload date, MIME type
- [ ] AC4: Пагінація для великих колекцій
- [ ] AC5: Пошук за filename/key
- [ ] AC6: Фільтр за MIME type (images, documents, videos)
- [ ] AC7: Сортування за датою (newest/oldest) та розміром
- [ ] AC8: Вибір одного або кількох файлів для видалення
- [ ] AC9: Delete з confirmation modal (кількість файлів, загальний розмір)
- [ ] AC10: Якщо файл використовується (refCount > 0) — warning "Used by N lessons"
- [ ] AC11: Кнопка "Copy URL" на кожному файлі, copies presigned URL, toast "URL copied"
- [ ] AC12: Upload button на сторінці — reuse existing upload endpoint

## Технічні нотатки
- PRD: A-5
- Новий backend endpoint: `GET /api/storage/files?search=&mimeType=&sort=date&order=desc&skip=0&take=20`
- Response: `{ data: StorageFile[], total: number }`
- Потребує таблицю StorageFile з S-E04-16
- Нові компоненти: file-management page, file-card, file-list
- Domain structure: `libs/staff/components/file-management/`
- Пріоритет: P2
- Оцінка: L (8-12 год)
