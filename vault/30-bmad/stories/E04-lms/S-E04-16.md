# S-E04-16: Дедуплікація файлів у MinIO

## Контекст
Кожне завантаження генерує новий UUID key. Якщо одне зображення завантажити 10 разів — 10 копій у MinIO. Це витрачає сховище та ускладнює управління файлами.

## User Story
Як система, я маю виявляти дублікати файлів за content hash, щоб не зберігати один файл кілька разів.

## Критерії приймання
- [ ] AC1: Перед завантаженням обчислюється SHA-256 hash вмісту файлу
- [ ] AC2: Перевірка наявності файлу з таким hash у таблиці StorageFile
- [ ] AC3: Якщо існує — повернути URL існуючого файлу, increment refCount
- [ ] AC4: Якщо новий — завантажити у MinIO, створити запис StorageFile
- [ ] AC5: При видаленні — decrement refCount; якщо 0 — видалити з MinIO та DB
- [ ] AC6: Concurrent uploads одного файлу — upsert з hash як unique constraint
- [ ] AC7: Existing files без hash — lazy compute при наступному зверненні

## Технічні нотатки
- PRD: STOR-1..6, DUP-1..3
- Prisma migration: створити таблицю `StorageFile` (id, key, hash, mimeType, size, refCount, createdAt)
- Index на `hash` для швидкого пошуку
- Зміни в `storage.service.ts`: upload flow та delete flow
- Пріоритет: P3
- Оцінка: M (4-6 год)
