# S-E05-06: Статуси зустрічі та життєвий цикл

## Контекст
Точний облік проведених сесій необхідний для оцінки навантаження консультантів (E09 Workload), аналітики ефективності (E11 Analytics) та контролю якості супервізорами. Автоматичне визначення no_show через 15 хвилин звільняє консультанта від ручного оновлення статусу та тригерить протоколи обробки неявки.

## User Story
Як Consultant, я хочу керувати статусами зустрічі (scheduled, completed, cancelled, no_show), щоб мати точний облік проведених сесій.

## Критерії приймання
- [x] AC1: Зустріч має статуси: scheduled -> completed / cancelled / no_show
- [x] AC2: Консультант може позначити зустріч як completed або cancelled
- [x] AC3: Статус no_show встановлюється автоматично через 15 хвилин після запланованого часу без участі обох сторін
