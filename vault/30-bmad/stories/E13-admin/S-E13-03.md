# S-E13-03: Захист останнього адмiнiстратора

## Контекст
Система без адміністратора стає некерованою — ніхто не зможе створювати користувачів, змінювати налаштування або реагувати на інциденти. Захист останнього адміна від випадкового видалення або зміни ролі є критичним для безперервності роботи платформи. Атомарна перевірка на рівні БД запобігає race condition при одночасних операціях.

## User Story
Як система, я хочу запобiгти видаленню або деактивацiї останнього адмiна, щоб система завжди мала адмiнiстратора.

## Критерiї приймання
- [ ] AC1: Якщо в системi залишився один користувач з роллю Admin — зняття ролi Admin заблоковано
- [ ] AC2: Деактивацiя останнього адмiна заблокована
- [ ] AC3: При спробi виконати заблоковану дiю — повiдомлення "Неможливо видалити останнього адмiнiстратора системи"

## Технiчнi нотатки
- Перевiрка кiлькостi активних адмiнiв перед кожною операцiєю змiни ролi/деактивацiї
- Атомарна перевiрка на рiвнi БД для уникнення race condition

## Залежностi
- S-E13-01 — CRUD користувачiв, де виконується перевiрка
