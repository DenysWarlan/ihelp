# S-E13-01: CRUD користувачiв та призначення ролей

## Контекст
Управління командою є базовою функцією адмін-панелі. Система ролей (Consultant, Supervisor, Coordinator, Admin) визначає доступ до функціоналу по всій платформі. Обмеження "одна роль на користувача" спрощує рольову модель та запобігає конфліктам дозволів. Деактивація замість видалення (soft delete) зберігає цілісність історичних даних.

## User Story
Як адмiнiстратор, я хочу створювати, переглядати, редагувати та деактивувати акаунти staff-користувачiв, щоб управляти командою платформи (A-1).

## Критерiї приймання
- [ ] AC1: Адмiн може створити staff-користувача (Consultant, Supervisor, Coordinator, Admin) через invite (email)
- [ ] AC2: Кожен staff-користувач має рiвно одну роль; спроба призначити другу роль вiдхиляється з повiдомленням "Користувач вже має роль [X]"
- [ ] AC3: Адмiн може деактивувати акаунт — деактивований користувач не може увiйти в систему
- [ ] AC4: Адмiн може змiнити роль користувача (з перевiркою обмежень)
- [ ] AC5: Список користувачiв з пошуком та фiльтрацiєю по ролi, статусу (активний/деактивований)

## Технiчнi нотатки
- Soft delete для деактивацiї — данi зберiгаються
