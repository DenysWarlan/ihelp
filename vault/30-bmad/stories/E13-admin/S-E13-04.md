# S-E13-04: Блокування видалення консультанта з активними кейсами

## Контекст
Це дзеркальна сторі до S-E10-07, але з боку адмін-панелі. Адміністратор може намагатися деактивувати консультанта, не знаючи про його активні кейси. Блокування з інформативним повідомленням та посиланням на процес трансферу (E10) забезпечує, що люди не залишаться без підтримки через адміністративну дію.

## User Story
Як система, я хочу блокувати видалення консультанта з активними кейсами, щоб не залишити людей без пiдтримки (EDGE-70).

## Критерiї приймання
- [ ] AC1: При спробi видалити/деактивувати консультанта з активними кейсами — операцiя блокується
- [ ] AC2: Адмiн бачить повiдомлення: "У цього консультанта N активних кейсiв. Спочатку перерозподiлiть кейси"
- [ ] AC3: Пiсля трансферу всiх кейсiв (E10 Transfer) деактивацiя стає доступною

## Технiчнi нотатки
- Soft delete — данi зберiгаються пiсля деактивацiї

## Залежностi
- E02 (Care Cases) — перевiрка наявностi активних кейсiв
- E10 (Case Transfer) — трансфер кейсiв перед деактивацiєю
- S-E10-07 — аналогiчне блокування з боку консультанта
