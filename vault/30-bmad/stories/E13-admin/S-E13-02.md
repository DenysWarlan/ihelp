# S-E13-02: Invite-based реєстрацiя staff

## Контекст
Контроль доступу до платформи починається з реєстрації. Invite-based підхід гарантує, що тільки авторизовані особи отримують доступ до системи з чутливими даними. Atomic token claim захищає від race condition при одночасному використанні запрошення. TTL 72 години забезпечує баланс між зручністю та безпекою.

## User Story
Як адмiнiстратор, я хочу запрошувати нових staff-користувачiв через email, щоб контролювати хто отримує доступ до системи (AUTH-5).

## Критерiї приймання
- [ ] AC1: При створеннi staff-користувача надсилається email-запрошення з унiкальним посиланням
- [ ] AC2: Токен запрошення дiйсний 72 години та є одноразовим (single-use)
- [ ] AC3: Token claim є atomic (захист вiд race condition при одночасному використаннi)
- [ ] AC4: Повторне використання або протухлий токен показує повiдомлення "Посилання недiйсне" з можливiстю адмiну надiслати нове запрошення
- [ ] AC5: Адмiн бачить статус запрошення: надiслано, використано, протухло

## Технiчнi нотатки
- Atomic token claim через SELECT FOR UPDATE або аналог
