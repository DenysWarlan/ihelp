# S-E13-10: Аудит-лог адмiнiстративних дiй

## Контекст
Аудит-лог є основою для розслідування інцидентів, забезпечення відповідальності та виконання вимог GDPR. Фіксація всіх адміністративних дій (з деталями "old value -> new value") дозволяє відстежити будь-яку зміну в системі. Append-only формат та заборона на модифікацію записів гарантують цілісність журналу. Спільна інфраструктура з S-E12-10 забезпечує єдиний підхід до аудиту.

## User Story
Як адмiнiстратор, я хочу мати журнал усiх адмiнiстративних дiй, щоб вiдстежувати змiни та розслiдувати iнциденти.

## Критерiї приймання
- [ ] AC1: Всi адмiн-дiї фiксуються: створення/змiна/видалення користувачiв, змiна налаштувань, змiна iнтеграцiй, змiна курсiв
- [ ] AC2: Кожен запис мiстить: хто, коли, тип дiї, деталi змiн (old value -> new value)
- [ ] AC3: Фiльтрацiя по користувачу, датi, типу дiї
- [ ] AC4: Аудит-лог є append-only — записи не можна змiнювати або видаляти
- [ ] AC5: Пагiнацiя для великих обсягiв записiв

## Технiчнi нотатки
- Окрема таблиця audit_log з iндексами на user_id, created_at, action_type
- Спiльна iнфраструктура аудит-логу з E12 GDPR
