# S-E12-06: Взаємне блокування експорту та анонiмiзацiї

## Контекст
Одночасне виконання експорту та анонімізації для одного Person може призвести до неконсистентних даних: експорт може містити частково анонімізовані дані, або анонімізація може зачепити дані під час їх збирання для експорту. Mutex на рівні бази даних гарантує атомарність та цілісність обох операцій.

## User Story
Як система, я хочу запобiгти одночасному виконанню експорту та анонiмiзацiї для одного Person, щоб забезпечити цiлiснiсть даних.

## Критерiї приймання
- [ ] AC1: Якщо для Person вже виконується експорт — запит на анонiмiзацiю блокується з повiдомленням "Зачекайте завершення поточної операцiї з даними"
- [ ] AC2: Якщо для Person виконується анонiмiзацiя — запит на експорт блокується з аналогiчним повiдомленням
- [ ] AC3: Блокування реалiзовано на рiвнi бази даних (mutex/lock на запис Person)

## Технiчнi нотатки
- Використовувати advisory lock або row-level lock на рiвнi PostgreSQL
- Операцiї мають виконуватись асинхронно (queue/background job)
