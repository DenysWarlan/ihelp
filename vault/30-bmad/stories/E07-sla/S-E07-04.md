# S-E07-04: Пауза та перезапуск SLA-таймера

## Контекст
Кейси можуть переходити у стан паузи (наприклад, коли людина не відповідає або потрібен час на обдумування). Без коректної зупинки SLA-таймера під час паузи метрики будуть спотворені, а консультанти отримуватимуть хибні ескалації. Ця сторі забезпечує справедливий облік SLA з урахуванням життєвого циклу кейсу (E02).

## User Story
Як координатор, я хочу щоб SLA-таймер автоматично зупинявся при паузi кейсу та перезапускався при новому повiдомленнi, щоб SLA-метрики вiдображали реальний час очiкування людини.

## Критерiї приймання
- [x] AC1: При переходi кейсу в статус "пауза" — SLA-таймер зупиняється
- [x] AC2: При надходженнi нового повiдомлення до кейсу на паузi — SLA-таймер перезапускається з нуля (tier reset)
- [x] AC3: Кейс автоматично переходить зi статусу "пауза" в "в роботi" при новому повiдомленнi
- [x] AC4: Усi pending ескалацiйнi job-и скасовуються при паузi та створюються заново при перезапуску

## Технiчнi нотатки
- Потрiбна атомарна операцiя: змiна статусу + скасування/створення SLA job-iв

## Залежностi
- E02 (Care Cases) — life cycle кейсу, статус "пауза"
- S-E07-02 — ескалацiйнi job-и що скасовуються/створюються
