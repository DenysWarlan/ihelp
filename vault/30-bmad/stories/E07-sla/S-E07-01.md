# S-E07-01: Автоматичний старт SLA-таймера при створеннi кейсу

## Контекст
SLA-моніторинг є фундаментом контролю якості обслуговування. Без автоматичного старту таймера з першої секунди звернення неможливо гарантувати, що кожен кейс буде оброблений вчасно. Ця сторі закладає основу для всіх наступних механізмів ескалації (S-E07-02) та трекінгу (S-E07-03).

## User Story
Як координатор, я хочу щоб SLA-таймер стартував автоматично при створеннi нового кейсу, щоб кожне звернення трекалось з першої секунди без ручного втручання.

## Критерiї приймання
- [x] AC1: SLA-таймер стартує автоматично при створеннi кейсу (статус "нове")
- [x] AC2: SLA вимiрюється за оригiнальним `message.createdAt` повiдомлення платформи, а НЕ за часом отримання webhook
- [x] AC3: При затримцi доставки webhook вiд Telegram SLA рахується вiд моменту фактичного вiдправлення повiдомлення людиною
- [x] AC4: Таймер зберiгає посилання на кейс та початковий timestamp

## Технiчнi нотатки
- Використовувати Bull queue для планування ескалацiйних job-iв
- Залежнiсть: E03 (Omnichannel Chat) для отримання оригiнальних timestamp-iв

## Залежностi
- E03 (Omnichannel Chat) — отримання оригiнальних timestamp повiдомлень платформи
