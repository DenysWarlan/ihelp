# S-E07-07: Скасування ескалацiї при вiдповiдi консультанта

## Контекст
Коли консультант відповідає на повідомлення людини, всі заплановані ескалації стають неактуальними. Без автоматичного скасування координатор та адмін отримуватимуть хибні сповіщення, що підриває довіру до системи SLA. Ця сторі є зворотним механізмом до S-E07-02 (ескалація) і запускає новий SLA-цикл для наступного повідомлення.

## User Story
Як консультант, я хочу щоб при моїй вiдповiдi на повiдомлення людини SLA-ескалацiя автоматично скасовувалась, щоб координатор та адмiн не отримували хибних сповiщень.

## Критерiї приймання
- [ ] AC1: При вiдправцi повiдомлення консультантом у кейс — усi pending ескалацiйнi job-и для цього кейсу скасовуються
- [ ] AC2: SLA-таймер для першої вiдповiдi фiксує фактичний час реакцiї
- [ ] AC3: Новий SLA-цикл стартує для наступного повiдомлення людини

## Технiчнi нотатки
- Потрiбно зв'язати Bull job ID з кейсом для швидкого скасування
- Подiя "consultant_replied" повинна тригерити скасування через event bus

## Залежностi
- S-E07-02 — ескалацiйнi job-и, що скасовуються
- S-E07-01 — фiксацiя часу реакцiї
