# Тест-кейси: S-E17-06 — Docker Compose (dev stack)

## Контекст
Ця сторія реалізує Docker Compose конфігурацію для локального dev-стеку (postgres, redis, minio, backend, frontend). Тести перевіряють запуск повного стеку за < 2 хвилини, hot-reload при зміні коду та збереження даних між перезапусками завдяки volumes.

### TC-S-E17-S06-01: Запуск повного dev-стеку
- **Передумови:** Docker та Docker Compose встановлені; `.env` файл заповнений
- **Кроки:**
  1. Виконати `docker compose up`
  2. Виміряти час старту
  3. Перевірити доступність кожного сервісу
- **Очікуваний результат:** Повний стек (postgres, redis, minio, backend, frontend) піднімається за < 2 хвилини; всі сервіси доступні
- **Пріоритет:** Високий

### TC-S-E17-S06-02: Hot-reload у dev-режимі
- **Передумови:** Dev-стек запущений через docker compose
- **Кроки:**
  1. Змінити файл у backend (NestJS)
  2. Змінити файл у frontend (Angular)
  3. Перевірити автоматичне перезавантаження
- **Очікуваний результат:** Backend та frontend автоматично перезавантажуються при зміні файлів
- **Пріоритет:** Середній

### TC-S-E17-S06-03: Збереження даних між перезапусками
- **Передумови:** Dev-стек з даними у PostgreSQL та MinIO
- **Кроки:**
  1. Додати дані у базу та файли у MinIO
  2. Виконати `docker compose down`
  3. Виконати `docker compose up`
  4. Перевірити наявність даних
- **Очікуваний результат:** Дані PostgreSQL та MinIO збережені між перезапусками завдяки volumes
- **Пріоритет:** Середній
