# Тест-кейси: S-E17-01 — NestJS Backend Scaffold

## Контекст
Ця сторія реалізує базовий NestJS backend з модульною структурою, health check ендпоінтом та глобальними middleware. Тести перевіряють наявність модулів (auth, cases, chat, lms, users), health check, уніфікований формат помилок, валідацію запитів через class-validator та перевірку environment змінних при старті.

### TC-S-E17-S01-01: Модульна структура та health check
- **Передумови:** NestJS проєкт ініціалізований
- **Кроки:**
  1. Перевірити наявність модулів: auth, cases, chat, lms, users (порожні)
  2. Запустити backend
  3. Відправити GET `/health`
- **Очікуваний результат:** Модулі існують у структурі проєкту; `/health` відповідає 200 OK
- **Пріоритет:** Високий

### TC-S-E17-S01-02: Global exception filter
- **Передумови:** Backend запущений
- **Кроки:**
  1. Викликати ендпоінт, що генерує необроблену помилку
  2. Перевірити формат відповіді
- **Очікуваний результат:** Помилка повертається у уніфікованому JSON-форматі (statusCode, message, timestamp, path)
- **Пріоритет:** Високий

### TC-S-E17-S01-03: Request validation через class-validator
- **Передумови:** Backend запущений; є ендпоінт з DTO-валідацією
- **Кроки:**
  1. Відправити запит з невалідними даними (порожні обов'язкові поля, некоректні типи)
  2. Перевірити відповідь
- **Очікуваний результат:** Відповідь 400 Bad Request з детальними повідомленнями валідації
- **Пріоритет:** Високий

### TC-S-E17-S01-04: Environment validation при старті
- **Передумови:** `.env` файл з відсутніми обов'язковими змінними
- **Кроки:**
  1. Видалити обов'язкову змінну з `.env` (наприклад, DATABASE_URL)
  2. Спробувати запустити backend
- **Очікуваний результат:** Backend НЕ стартує; у логах — чітке повідомлення про відсутню змінну
- **Пріоритет:** Високий
