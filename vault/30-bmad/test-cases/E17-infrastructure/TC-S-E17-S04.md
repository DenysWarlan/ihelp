# Тест-кейси: S-E17-04 — Redis — Bull Queues та Socket.io Adapter

## Контекст
Ця сторія інтегрує Redis для Bull queues (email, notifications, SLA timers) та Socket.io adapter для горизонтального масштабування WebSocket-з'єднань. Тести перевіряють підключення до Redis, обробку завдань через Bull queues, доставку повідомлень через Redis adapter між інстансами та стабільність при навантаженні 200 одночасних WebSocket-з'єднань.

### TC-S-E17-S04-01: Підключення Redis та Bull queues
- **Передумови:** Redis запущений; backend налаштований
- **Кроки:**
  1. Запустити backend
  2. Перевірити підключення до Redis
  3. Додати завдання у Bull queue (email)
  4. Перевірити обробку завдання
- **Очікуваний результат:** Redis підключений; Bull queue приймає та обробляє завдання для email, notifications, SLA timers
- **Пріоритет:** Високий

### TC-S-E17-S04-02: Socket.io Redis adapter
- **Передумови:** Два інстанси backend з Redis adapter
- **Кроки:**
  1. Клієнт підключається до інстансу A через WebSocket
  2. Інстанс B надсилає повідомлення через Socket.io
- **Очікуваний результат:** Повідомлення доставляється клієнту через Redis adapter; горизонтальне масштабування працює
- **Пріоритет:** Середній

### TC-S-E17-S04-03: Навантаження WebSocket-з'єднань
- **Передумови:** Backend запущений з Redis adapter
- **Кроки:**
  1. Створити 200 одночасних WebSocket-з'єднань
  2. Перевірити стабільність системи
- **Очікуваний результат:** Система стабільно підтримує 200 одночасних WebSocket-з'єднань (PRD 5.1)
- **Пріоритет:** Середній
