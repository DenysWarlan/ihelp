# Тест-кейси: S-E09-04 — Out-of-band ескалацiя при forced logout координатора

## Контекст
Ця сторi забезпечує доставку ескалацiй координатору навiть при forced logout через зовнiшнi канали (SMS, email). Тести перевiряють доставку через SMS/email незалежно вiд стану сесiї та fallback chain при невдалiй доставцi.

### TC-S-E09-S04-01: SMS/email при forced logout координатора
- **Передумови:** Координатор у станi forced logout (AUTH-8); кризовi слоти вичерпанi
- **Кроки:**
  1. Система спробує ескалювати переповнення кризових слотiв координатору
- **Очiкуваний результат:** SMS та email доставляються незалежно вiд стану сесiї координатора; in-app push вiдправляється додатково, але НЕ як єдиний канал
- **Прiоритет:** Високий

### TC-S-E09-S04-02: Fallback chain SMS -> push -> email -> phone call
- **Передумови:** Ескалацiя overflow кризових слотiв
- **Кроки:**
  1. SMS не доставлено
  2. Push не доставлено
  3. Email не доставлено
- **Очiкуваний результат:** Fallback chain активується послiдовно: SMS -> push -> email -> phone call
- **Прiоритет:** Високий

### TC-S-E09-S04-03: Звичайний overflow без forced logout
- **Передумови:** Координатор активний (не forced logout); кризовi слоти вичерпанi
- **Кроки:**
  1. Система ескалює overflow координатору
- **Очiкуваний результат:** Ескалацiя доставляється через in-app push та SMS/email одночасно
- **Прiоритет:** Середнiй
