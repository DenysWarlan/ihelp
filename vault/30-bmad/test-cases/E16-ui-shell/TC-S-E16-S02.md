# Тест-кейси: S-E16-02 — Публічний Navbar

## Контекст
Ця сторія реалізує публічний navbar з різними станами для Guest та авторизованого Person. Тести перевіряють навігаційні елементи для кожного стану, responsive-поведінку (hamburger-меню на mobile) та доступність через клавіатурну навігацію.

### TC-S-E16-S02-01: Navbar для Guest
- **Передумови:** Користувач не авторизований
- **Кроки:**
  1. Відкрити будь-яку публічну сторінку
  2. Перевірити вміст navbar
  3. Натиснути на логотип, "Курси", "Увійти"
- **Очікуваний результат:** Логотип веде на `/`; "Курси" на `/courses`; "Увійти" на `/login`
- **Пріоритет:** Високий

### TC-S-E16-S02-02: Navbar для авторизованого Person
- **Передумови:** Person авторизований
- **Кроки:**
  1. Відкрити публічну сторінку
  2. Перевірити navbar
  3. Натиснути на ім'я/аватар
- **Очікуваний результат:** Замість "Увійти" — ім'я/аватар Person; dropdown містить "Кабінет" (-> `/my`) та "Вийти"
- **Пріоритет:** Високий

### TC-S-E16-S02-03: Navbar responsive — hamburger-меню
- **Передумови:** Mobile viewport (< 768px)
- **Кроки:**
  1. Відкрити публічну сторінку на mobile
  2. Натиснути hamburger-іконку
  3. Перевірити пункти меню
- **Очікуваний результат:** Navbar згортається у hamburger-іконку; при натисканні — меню розгортається з усіма пунктами
- **Пріоритет:** Середній

### TC-S-E16-S02-04: Доступність navbar
- **Передумови:** Клавіатура, screen reader
- **Кроки:**
  1. Навігація через Tab між елементами navbar
  2. Перевірити focus states
  3. Перевірити aria labels
- **Очікуваний результат:** Всі елементи доступні через keyboard navigation; видимі focus states; коректні aria labels
- **Пріоритет:** Середній
