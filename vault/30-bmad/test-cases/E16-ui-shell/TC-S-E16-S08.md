# Тест-кейси: S-E16-08 — Базові UI-компоненти (частина 2 — відображення даних)

## Контекст
Ця сторія реалізує UI-компоненти для відображення даних (Badge, Card, Progress Bar, Alert Banner, Table). Тести перевіряють коректне відображення статусів та пріоритетів через Badge, функціональність Card та Progress Bar, варіанти Alert Banner та responsive-поведінку Table.

### TC-S-E16-S08-01: Badge для статусів та пріоритетів
- **Передумови:** Badge компонент реалізований
- **Кроки:**
  1. Створити Badge з різними статусами кейсів (нове, в роботі, закрито)
  2. Створити Badge з різними пріоритетами
- **Очікуваний результат:** Кольори Badge відповідають design tokens для кожного статусу та пріоритету
- **Пріоритет:** Середній

### TC-S-E16-S08-02: Card, Progress Bar та Alert Banner
- **Передумови:** Компоненти реалізовані
- **Кроки:**
  1. Card: створити контейнер для курсу з заголовком та описом
  2. Progress Bar: відобразити прогрес 60% з числовим значенням
  3. Alert Banner: перевірити варіанти crisis (червоний), SLA warning (жовтий), info (синій)
- **Очікуваний результат:** Card відображає контент; Progress Bar показує заповнення та відсоток; Alert Banner має відповідні кольори для кожного варіанту
- **Пріоритет:** Високий

### TC-S-E16-S08-03: Table — responsive поведінка
- **Передумови:** Table компонент з даними (5+ рядків, 4+ колонок)
- **Кроки:**
  1. Відкрити на desktop — перевірити таблицю
  2. Відкрити на mobile — перевірити адаптацію
  3. Натиснути на заголовок колонки для сортування
- **Очікуваний результат:** Desktop: звичайна таблиця; Mobile: stacked layout або горизонтальний scroll; сортування працює
- **Пріоритет:** Високий
