# Тест-кейси: S-E01-05 — Рольова модель та Guards

## Контекст
Ця історія реалізує рольову модель доступу з п'ятьма ролями (Person, Consultant, Supervisor, Coordinator, Admin) та Guards для захисту ендпоінтів. Тести перевіряють коректну авторизацію за роллю, блокування неавторизованого доступу (401) та доступу з недостатніми правами (403).

### TC-S-E01-S05-01: Доступ до ендпоінту з правильною роллю
- **Передумови:** Користувач авторизований з роллю Consultant
- **Кроки:**
  1. Консультант надсилає запит до ендпоінту, доступного для ролі Consultant
- **Очікуваний результат:** Запит виконується успішно (200 OK)
- **Пріоритет:** Високий

### TC-S-E01-S05-02: Доступ до ендпоінту без авторизації
- **Передумови:** Користувач не авторизований (немає JWT)
- **Кроки:**
  1. Неавторизований користувач надсилає запит до захищеного ендпоінту
- **Очікуваний результат:** API повертає 401 Unauthorized
- **Пріоритет:** Високий

### TC-S-E01-S05-03: Доступ до ендпоінту з недостатніми правами
- **Передумови:** Person авторизований з роллю Person
- **Кроки:**
  1. Person надсилає запит до ендпоінту, доступного тільки для Admin
- **Очікуваний результат:** API повертає 403 Forbidden
- **Пріоритет:** Високий

### TC-S-E01-S05-04: Перевірка всіх п'яти ролей
- **Передумови:** Існують користувачі з кожною з 5 ролей
- **Кроки:**
  1. Для кожної ролі (Person, Consultant, Supervisor, Coordinator, Admin) виконується запит до ендпоінту з обмеженим доступом
- **Очікуваний результат:** Доступ надається/блокується відповідно до конфігурації @Roles() декоратора
- **Пріоритет:** Високий
