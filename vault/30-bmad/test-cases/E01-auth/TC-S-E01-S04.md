# Тест-кейси: S-E01-04 — JWT токени з rotation та crisis session

## Контекст
Ця історія реалізує безпечне управління JWT-токенами з ротацією refresh-токенів та захистом кризових сесій. Тести перевіряють коректну ротацію токенів, виявлення replay-атак з інвалідацією всієї token family, збереження кризових сесій під час forced logout та silent refresh під час активних операцій.

### TC-S-E01-S04-01: Успішна ротація refresh token
- **Передумови:** Person авторизований; має валідний refresh token
- **Кроки:**
  1. Access token спливає
  2. Клієнт надсилає refresh token для отримання нової пари
- **Очікуваний результат:** Видається новий access + refresh token; попередній refresh token інвалідується
- **Пріоритет:** Високий

### TC-S-E01-S04-02: Replay attack з використанням інвалідованого refresh token
- **Передумови:** Person авторизований; refresh token вже використаний і замінений новим
- **Кроки:**
  1. Зловмисник намагається використати старий (інвалідований) refresh token
- **Очікуваний результат:** Вся token family відкликається; forced logout на всіх пристроях
- **Пріоритет:** Високий

### TC-S-E01-S04-03: Кризова сесія не переривається forced logout
- **Передумови:** Активна кризова сесія (crisis session flag встановлений)
- **Кроки:**
  1. Система ініціює forced logout (наприклад, через replay attack detection)
  2. Перевіряється наявність кризової сесії
- **Очікуваний результат:** Кризова сесія залишається активною протягом 24 годин; forced logout не застосовується
- **Пріоритет:** Високий

### TC-S-E01-S04-04: Закінчення 24-годинного вікна кризової сесії
- **Передумови:** Кризова сесія активна більше 24 годин
- **Кроки:**
  1. Проходить 24 години з моменту початку кризової сесії
  2. Система перевіряє статус сесії
- **Очікуваний результат:** Продовження сесії можливе тільки з затвердженням супервізора; подія логується в audit log
- **Пріоритет:** Середній

### TC-S-E01-S04-05: Silent token refresh під час upload
- **Передумови:** Person завантажує файл; access token спливає під час upload
- **Кроки:**
  1. Person розпочинає upload файлу
  2. Access token спливає під час завантаження
  3. Клієнт виконує silent refresh
- **Очікуваний результат:** Завантаження продовжується без перерви; прогрес не втрачається
- **Пріоритет:** Середній
