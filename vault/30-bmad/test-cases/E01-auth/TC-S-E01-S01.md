# Тест-кейси: S-E01-01 — OAuth-автентифікація Person

## Контекст
Ця історія охоплює вхід Person через зовнішніх OAuth-провайдерів (Google, Facebook, Telegram). Тести перевіряють успішну автентифікацію через кожен провайдер, отримання JWT-токенів та коректну обробку помилок OAuth-провайдерів.

### TC-S-E01-S01-01: Успішний вхід через Google OAuth
- **Передумови:** Person має акаунт Google; платформа сконфігурована з Google OAuth credentials
- **Кроки:**
  1. Person натискає "Увійти через Google"
  2. Проходить автентифікацію в Google
  3. Google повертає callback з authorization code
- **Очікуваний результат:** Person отримує JWT (access + refresh токени); вхід успішний
- **Пріоритет:** Високий

### TC-S-E01-S01-02: Успішний вхід через Facebook OAuth
- **Передумови:** Person має акаунт Facebook; платформа сконфігурована з Facebook OAuth credentials
- **Кроки:**
  1. Person натискає "Увійти через Facebook"
  2. Проходить автентифікацію в Facebook
  3. Facebook повертає callback з authorization code
- **Очікуваний результат:** Person отримує JWT (access + refresh токени); вхід успішний
- **Пріоритет:** Високий

### TC-S-E01-S01-03: Успішний вхід через Telegram Login Widget
- **Передумови:** Person має акаунт Telegram; Telegram Login Widget налаштований
- **Кроки:**
  1. Person натискає "Увійти через Telegram"
  2. Підтверджує авторизацію в Telegram
  3. Telegram повертає auth data з hash
- **Очікуваний результат:** Person отримує JWT (access + refresh токени); вхід успішний
- **Пріоритет:** Високий

### TC-S-E01-S01-04: Помилка OAuth-провайдера
- **Передумови:** Person розпочинає OAuth flow
- **Кроки:**
  1. Person натискає "Увійти через Google"
  2. Google повертає помилку (timeout, відхилення авторизації, невалідний токен)
- **Очікуваний результат:** Відображається повідомлення про помилку з можливістю повторити спробу; JWT не видається
- **Пріоритет:** Високий
