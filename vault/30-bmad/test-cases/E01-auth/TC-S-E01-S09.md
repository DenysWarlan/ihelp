# Тест-кейси: S-E01-09 — Break-glass акаунт

## Контекст
Ця історія реалізує аварійний break-glass акаунт для відновлення доступу, коли всі адміни та супервізори заблоковані. Тести перевіряють активацію акаунту з фізичного носія, обов'язкову зміну credentials після використання та автоматичне надсилання алертів при активації.

### TC-S-E01-S09-01: Активація break-glass акаунту
- **Передумови:** Всі адміни та супервізори заблоковані; існує фізичний носій з credentials
- **Кроки:**
  1. Уповноважена особа вводить credentials з фізичного носія (sealed envelope / hardware token)
  2. Входить в систему
- **Очікуваний результат:** Доступ надано з повними адмін-правами; активація логується як critical incident
- **Пріоритет:** Високий

### TC-S-E01-S09-02: Обов'язкова зміна credentials після використання break-glass
- **Передумови:** Break-glass акаунт був використаний; доступ відновлено
- **Кроки:**
  1. Адмін відновлює доступ іншим акаунтам
  2. Завершує роботу з break-glass акаунтом
- **Очікуваний результат:** Система вимагає обов'язкову зміну credentials break-glass акаунту; проводиться аудит дій
- **Пріоритет:** Високий

### TC-S-E01-S09-03: Alert при активації break-glass
- **Передумови:** Break-glass акаунт не використовувався раніше
- **Кроки:**
  1. Хтось активує break-glass акаунт
- **Очікуваний результат:** Система надсилає alert у Slack/email всім зареєстрованим контактам
- **Пріоритет:** Середній
