# Тест-кейси: S-E03-01 — Веб-чат на Socket.io

## Контекст
Ця історія реалізує real-time веб-чат через Socket.io для обміну повідомленнями між Person та консультантом. Тести перевіряють обмін повідомленнями у реальному часі, авторизацію з'єднання через JWT, відхилення неавторизованих з'єднань та масштабування через Redis adapter.

### TC-S-E03-S01-01: Обмін повідомленнями через веб-чат у real-time
- **Передумови:** Person авторизований; кейс створений і має призначеного консультанта; Socket.io з'єднання встановлене
- **Кроки:**
  1. Person надсилає текстове повідомлення через веб-чат
  2. Консультант отримує повідомлення
  3. Консультант надсилає відповідь
- **Очікуваний результат:** Повідомлення доставляються обом сторонам у real-time без затримки перезавантаження
- **Пріоритет:** Високий

### TC-S-E03-S01-02: Авторизація Socket.io з'єднання через JWT
- **Передумови:** Person має валідний JWT
- **Кроки:**
  1. Person ініціює Socket.io handshake з JWT в заголовку
- **Очікуваний результат:** З'єднання встановлюється успішно
- **Пріоритет:** Високий

### TC-S-E03-S01-03: Відхилення Socket.io з'єднання без JWT
- **Передумови:** Користувач без JWT або з невалідним JWT
- **Кроки:**
  1. Користувач намагається встановити Socket.io з'єднання без авторизації
- **Очікуваний результат:** З'єднання відхиляється; помилка авторизації
- **Пріоритет:** Високий

### TC-S-E03-S01-04: Multi-instance scaling через Redis adapter
- **Передумови:** Два інстанси сервера з Redis adapter; Person підключений до інстансу A, консультант -- до інстансу B
- **Кроки:**
  1. Person надсилає повідомлення через інстанс A
- **Очікуваний результат:** Консультант отримує повідомлення через інстанс B завдяки Redis adapter
- **Пріоритет:** Середній
