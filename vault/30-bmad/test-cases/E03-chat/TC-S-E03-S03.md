# Тест-кейси: S-E03-03 — Unified Message Bus та єдина модель повідомлення

## Контекст
Ця історія реалізує єдину модель повідомлення для всіх каналів комунікації. Тести перевіряють збереження повідомлень з усіма обов'язковими полями, відхилення непідтримуваних каналів, XSS-санітизацію контенту та збереження повідомлень з різних каналів в єдиній таблиці.

### TC-S-E03-S03-01: Збереження повідомлення з усіма полями моделі
- **Передумови:** Person надсилає повідомлення через веб-чат
- **Кроки:**
  1. Person надсилає повідомлення
  2. Перевіряється збережений запис у БД
- **Очікуваний результат:** Повідомлення містить всі поля: id, careCaseId, senderId, senderRole, channel, channelChatId, content, attachments, createdAt
- **Пріоритет:** Високий

### TC-S-E03-S03-02: Повідомлення з непідтримуваного каналу
- **Передумови:** API отримує повідомлення з каналом "viber" або "instagram"
- **Кроки:**
  1. Надходить повідомлення з channel = "viber"
- **Очікуваний результат:** API повертає 422 з повідомленням "Канал viber ще не підтримується"
- **Пріоритет:** Високий

### TC-S-E03-S03-03: XSS-санітизація контенту повідомлення
- **Передумови:** Person надсилає повідомлення з HTML/JS кодом
- **Кроки:**
  1. Person надсилає повідомлення з вмістом `<script>alert('xss')</script>`
- **Очікуваний результат:** Контент санітизується перед збереженням (DOMPurify, strip ALL HTML); скрипт видалено
- **Пріоритет:** Високий

### TC-S-E03-S03-04: Збереження повідомлень з різних каналів в єдиній таблиці
- **Передумови:** Person надсилає повідомлення з web та Telegram
- **Кроки:**
  1. Person надсилає повідомлення через веб-чат (channel = "web")
  2. Person надсилає повідомлення через Telegram (channel = "telegram")
- **Очікуваний результат:** Обидва повідомлення зберігаються в єдиній таблиці Message з відповідним channel
- **Пріоритет:** Високий
