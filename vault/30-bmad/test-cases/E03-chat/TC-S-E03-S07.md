# Тест-кейси: S-E03-07 — Ordering та дедуплікація webhook-повідомлень

## Контекст
Ця історія забезпечує правильний порядок відображення повідомлень за оригінальним timestamp та дедуплікацію повторних webhook-запитів. Тести перевіряють сортування за оригінальним часом (а не часом доставки), дедуплікацію через unique constraint та idempotent processing.

### TC-S-E03-S07-01: Сортування за оригінальним timestamp
- **Передумови:** Два webhook-повідомлення надходять з різним порядком доставки
- **Кроки:**
  1. Повідомлення A (timestamp 10:01) надходить на webhook о 10:05
  2. Повідомлення B (timestamp 10:02) надходить на webhook о 10:03
- **Очікуваний результат:** В інтерфейсі повідомлення сортуються за оригінальним timestamp: A (10:01), B (10:02)
- **Пріоритет:** Високий

### TC-S-E03-S07-02: Дедуплікація повторних webhook
- **Передумови:** Telegram надсилає повторний webhook з тим самим message_id
- **Кроки:**
  1. Webhook з message_id = 12345 обробляється вперше
  2. Той самий webhook з message_id = 12345 надходить повторно
- **Очікуваний результат:** Повторний webhook ігнорується; дублікат не створюється (unique constraint на channel + channelMessageId)
- **Пріоритет:** Високий

### TC-S-E03-S07-03: Idempotent processing webhook
- **Передумови:** Webhook вже оброблений
- **Кроки:**
  1. Той самий webhook обробляється повторно (retry від Telegram)
- **Очікуваний результат:** Жодних побічних ефектів; повідомлення не дублюється; сповіщення не надсилається повторно
- **Пріоритет:** Високий
