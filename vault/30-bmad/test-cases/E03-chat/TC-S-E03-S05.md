# Тест-кейси: S-E03-05 — Маршрутизація відповіді та fallback chain

## Контекст
Ця історія реалізує автоматичну маршрутизацію відповідей консультанта в канал останнього повідомлення Person з fallback chain при недоступності каналу. Тести перевіряють маршрутизацію в активний канал, зміну каналу між повідомленнями, fallback при недоступності та health check перед відправкою.

### TC-S-E03-S05-01: Маршрутизація в канал останнього повідомлення
- **Передумови:** Person останнє повідомлення надіслав через Telegram
- **Кроки:**
  1. Консультант надсилає відповідь
- **Очікуваний результат:** Відповідь доставляється в Telegram
- **Пріоритет:** Високий

### TC-S-E03-S05-02: Зміна каналу між повідомленнями
- **Передумови:** Person надіслав повідомлення через Telegram, потім через web
- **Кроки:**
  1. Консультант надсилає відповідь
- **Очікуваний результат:** Відповідь доставляється через web (канал останнього повідомлення)
- **Пріоритет:** Високий

### TC-S-E03-S05-03: Fallback при недоступності каналу
- **Передумови:** Person останнє повідомлення через Telegram; Telegram Bot API недоступний
- **Кроки:**
  1. Консультант надсилає відповідь
  2. Health check виявляє недоступність Telegram
  3. Спрацьовує fallback chain
- **Очікуваний результат:** Повідомлення доставляється через fallback канал (email або web push); адмін отримує алерт
- **Пріоритет:** Високий

### TC-S-E03-S05-04: Health check каналу перед відправкою
- **Передумови:** Telegram Bot API доступний
- **Кроки:**
  1. Система виконує health check перед відправкою повідомлення
- **Очікуваний результат:** Перевірка проходить успішно; повідомлення відправляється в основний канал без fallback
- **Пріоритет:** Середній
