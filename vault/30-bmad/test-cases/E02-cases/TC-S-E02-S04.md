# Тест-кейси: S-E02-04 — Призначення консультанта

## Контекст
Ця історія реалізує ручне призначення консультанта координатором на кейс. Тести перевіряють успішне призначення з логуванням в audit log, блокування призначення для користувачів без прав координатора та коректність записів аудиту.

### TC-S-E02-S04-01: Ручне призначення консультанта координатором
- **Передумови:** Кейс зі статусом "new"; координатор авторизований
- **Кроки:**
  1. Координатор викликає POST /cases/:id/assign з consultantId
- **Очікуваний результат:** Консультант призначений; статус кейсу змінюється на "assigned"; дія логується в audit log
- **Пріоритет:** Високий

### TC-S-E02-S04-02: Спроба призначення консультанта без прав координатора
- **Передумови:** Користувач з роллю Person або Consultant
- **Кроки:**
  1. Користувач викликає POST /cases/:id/assign
- **Очікуваний результат:** API повертає 403 Forbidden
- **Пріоритет:** Високий

### TC-S-E02-S04-03: Призначення з логуванням в audit log
- **Передумови:** Координатор авторизований; кейс існує
- **Кроки:**
  1. Координатор призначає консультанта
  2. Перевіряється audit log
- **Очікуваний результат:** В audit log є запис з даними: хто призначив, кого призначив, коли
- **Пріоритет:** Середній
