# Тест-кейси: S-E02-07 — Optimistic locking

## Контекст
Ця історія реалізує optimistic locking для запобігання конфліктів при одночасному редагуванні кейсу. Тести перевіряють успішне оновлення з правильною версією та коректне повернення 409 Conflict при спробі оновлення з застарілою версією.

### TC-S-E02-S07-01: Успішне оновлення кейсу з правильною version
- **Передумови:** Кейс існує з version = 1
- **Кроки:**
  1. Консультант надсилає оновлення з version = 1
- **Очікуваний результат:** Оновлення успішне; повертається нова version = 2
- **Пріоритет:** Високий

### TC-S-E02-S07-02: Конфлікт при одночасному редагуванні
- **Передумови:** Кейс з version = 1; два консультанти завантажили кейс одночасно
- **Кроки:**
  1. Консультант A оновлює кейс з version = 1 (успішно, version стає 2)
  2. Консультант B намагається оновити кейс з version = 1
- **Очікуваний результат:** API повертає 409 Conflict з повідомленням "Кейс було змінено іншим користувачем" і пропозицією перезавантажити
- **Пріоритет:** Високий
