# Тест-кейси: S-E02-06 — Audit log дій по кейсу

## Контекст
Ця історія реалізує незмінний audit log для відстеження всіх дій по кейсу. Тести перевіряють логування змін статусу, розмежування доступу до audit log за ролями (тільки Supervisor, Coordinator, Admin) та незмінність записів (append-only).

### TC-S-E02-S06-01: Логування зміни статусу кейсу
- **Передумови:** Кейс існує; координатор авторизований
- **Кроки:**
  1. Координатор змінює статус кейсу (наприклад, assigned -> in_progress)
  2. Перевіряється audit log
- **Очікуваний результат:** В audit log є запис: хто, коли, з якого статусу на який
- **Пріоритет:** Високий

### TC-S-E02-S06-02: Доступ до audit log для різних ролей
- **Передумови:** Кейс має записи в audit log
- **Кроки:**
  1. Supervisor запитує audit log -- доступ надано
  2. Coordinator запитує audit log -- доступ надано
  3. Admin запитує audit log -- доступ надано
  4. Person запитує audit log -- доступ заборонено
  5. Consultant запитує audit log -- доступ заборонено
- **Очікуваний результат:** Audit log доступний тільки для Supervisor, Coordinator, Admin
- **Пріоритет:** Високий

### TC-S-E02-S06-03: Незмінність записів audit log
- **Передумови:** В audit log є записи
- **Кроки:**
  1. Спроба виконати UPDATE або DELETE на записі audit log
- **Очікуваний результат:** Операція заборонена; audit log є append-only
- **Пріоритет:** Високий
