# Тест-кейси: S-E08-09 — MFA bypass для acknowledgment кризового алерту

## Контекст
Ця сторi дозволяє черговому пiдтвердити кризовий алерт без повторного MFA при активнiй сесiї. Тести перевiряють bypass при активнiй сесiї, збереження MFA при неактивнiй сесiї та обмеження bypass тiльки для acknowledgment.

### TC-S-E08-S09-01: Acknowledgment без MFA при активнiй сесiї
- **Передумови:** Черговий має активну автентифiковану сесiю
- **Кроки:**
  1. Черговий отримує кризовий алерт
  2. Натискає "Пiдтвердити" (acknowledgment)
- **Очiкуваний результат:** Acknowledgment виконується без повторного MFA; факт bypass логується в audit log
- **Прiоритет:** Високий

### TC-S-E08-S09-02: MFA потрiбна при неактивнiй сесiї
- **Передумови:** Сесiя чергового протухла або неактивна
- **Кроки:**
  1. Черговий отримує кризовий алерт
  2. Натискає "Пiдтвердити" (acknowledgment)
- **Очiкуваний результат:** Стандартний MFA-потiк зберiгається; черговий проходить MFA перед acknowledgment
- **Прiоритет:** Високий

### TC-S-E08-S09-03: Bypass тiльки для acknowledgment кризового алерту
- **Передумови:** Черговий має активну сесiю
- **Кроки:**
  1. Черговий намагається виконати iншу захищену дiю (не acknowledgment)
- **Очiкуваний результат:** MFA bypass НЕ застосовується; потрiбна стандартна MFA для iнших дiй
- **Прiоритет:** Високий
