# Тест-кейси: S-E07-06 — Distributed lock на SLA record

## Контекст
Ця сторi забезпечує конкурентний доступ до SLA records через distributed lock. Тести перевiряють захист вiд одночасного оновлення, автоматичне звiльнення lock через TTL для запобiгання deadlock та retry з exponential backoff.

### TC-S-E07-S06-01: Захист вiд одночасного оновлення
- **Передумови:** Два сервiси намагаються одночасно оновити один SLA record
- **Кроки:**
  1. Сервiс A захоплює lock на SLA record
  2. Сервiс B намагається оновити той самий SLA record
- **Очiкуваний результат:** Сервiс B чекає або отримує помилку; данi SLA record не пошкоджуються
- **Прiоритет:** Високий

### TC-S-E07-S06-02: TTL запобiгає deadlock
- **Передумови:** Сервiс захопив lock та впав (crash)
- **Кроки:**
  1. Сервiс A захоплює lock
  2. Сервiс A падає без звiльнення lock
  3. Через TTL (5-10 секунд) iнший сервiс намагається захопити lock
- **Очiкуваний результат:** Lock автоматично звiльняється пiсля TTL; Сервiс B успiшно захоплює lock
- **Прiоритет:** Високий

### TC-S-E07-S06-03: Retry з exponential backoff
- **Передумови:** Lock зайнятий iншим сервiсом
- **Кроки:**
  1. Сервiс B намагається захопити зайнятий lock
- **Очiкуваний результат:** Система виконує retry з exponential backoff; пiсля звiльнення lock — успiшне захоплення
- **Прiоритет:** Середнiй
