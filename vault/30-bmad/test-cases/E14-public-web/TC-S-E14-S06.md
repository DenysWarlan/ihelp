# Тест-кейси: S-E14-06 — Підтвердження звернення

## Контекст
Ця сторія реалізує сторінку підтвердження після успішного відправлення форми звернення (`/request/success`). Тести перевіряють відображення елементів підтвердження (іконка, прогрес-бар, навігаційні посилання) та поведінку при прямому доступі до сторінки без попереднього відправлення форми.

### TC-S-E14-S06-01: Відображення сторінки підтвердження
- **Передумови:** Користувач успішно відправив форму звернення
- **Кроки:**
  1. Після відправлення форми перевірити сторінку `/request/success`
- **Очікуваний результат:** Відображається іконка успіху, 3-крокова шкала прогресу (надіслано -> обробляється -> консультант зв'яжеться), кнопка "Переглянути курси" та посилання на Telegram-бот
- **Пріоритет:** Високий

### TC-S-E14-S06-02: Навігація з підтвердження
- **Передумови:** Користувач на сторінці `/request/success`
- **Кроки:**
  1. Натиснути кнопку "Переглянути курси"
  2. Повернутися та натиснути посилання на Telegram-бот
- **Очікуваний результат:** "Переглянути курси" веде на `/courses`; посилання на Telegram-бот відкриває відповідний URL
- **Пріоритет:** Середній

### TC-S-E14-S06-03: Прямий доступ до сторінки підтвердження
- **Передумови:** Користувач НЕ відправляв форму звернення
- **Кроки:**
  1. Відкрити напряму URL `/request/success`
- **Очікуваний результат:** Сторінка доступна без авторизації (статичний контент); або перенаправлення на `/request`
- **Пріоритет:** Низький
