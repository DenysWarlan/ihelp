# E07 — SLA Monitor

## Мета

Забезпечити автоматичний трекiнг часу реагування консультантiв та багаторiвневу ескалацiю при порушеннi SLA, щоб жодне звернення не залишилось без вiдповiдi.

## Scope

### Включено

- Трекiнг часу вiд створення кейсу до першої вiдповiдi консультанта (SLA-1)
- Ескалацiйнi рiвнi: 4 год (push) → 12 год (push + email) → 24 год (координатор + автоперепризначення) → 48 год (адмiн) (SLA-2)
- Трекiнг часу мiж повiдомленнями людини та вiдповiддю консультанта (SLA-3)
- Real-time дашборд SLA-статусiв для координатора (SLA-5)
- Distributed lock на SLA record для запобiгання race condition (SLA-6)
- Пауза/перезапуск SLA-таймера при змiнi статусу кейсу

### Виключено

- Ескалацiя для переписки без вiдповiдi >48 год / >5 днiв / >7 днiв (SLA-4 — v1.1)
- Трекiнг мiж окремими повiдомленнями в рамках ескалацiї (v1.1)

## Критерiї приймання

- [ ] SLA-таймер стартує автоматично при створеннi кейсу
- [ ] SLA вимiрюється за `message.createdAt`, а не за часом отримання webhook
- [ ] Ескалацiя вiдправляється вiдповiдним ролям на кожному рiвнi
- [ ] Таймер зупиняється при переходi кейсу в "паузу" i перезапускається з нуля при новому повiдомленнi
- [ ] Координатор бачить real-time дашборд зi статусами SLA усiх кейсiв
- [ ] Паралельне оновлення SLA record не призводить до race condition
- [ ] При автоперепризначеннi (24 год) — SLA-таймер скидається для нового консультанта
