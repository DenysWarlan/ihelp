# E14 — Public Web (Landing + Intake)

## Мета

Надати публічну точку входу для людей, які потребують допомоги: лендінг з описом служби, каталог курсів з превью, форму звернення (intake) та модальне вікно авторизації для початку курсу.

## Скоуп

### Включено

- **Landing Page** (`/`): hero-секція, CTA "Потрібна допомога" та "Переглянути курси", блок переваг
- **Каталог курсів** (`/courses`): сітка карток (назва, опис, кількість уроків), банер "Потрібна допомога?"
- **Превью курсу** (`/courses/:id`): опис, список уроків (заблоковані), відео-трейлер, CTA "Почати курс"
- **Модальне вікно авторизації**: чекбокс згоди + OAuth (Google/Facebook/Telegram), rollback згоди при помилці OAuth
- **Форма звернення** (`/request`): ім'я, країна, мова, спосіб зв'язку, тема, опис, два GDPR-чекбокси
- **Підтвердження** (`/request/success`): 3-крокова шкала, кнопка "Переглянути курси", посилання на Telegram-бот
- **Person Login** (`/login`): окрема сторінка входу з трьома OAuth-провайдерами

### Виключено

- Telegram-бот intake (E03)
- Enrollment, progress tracking, перегляд уроків (E04, E15)
- Staff login (E01)
- SEO-оптимізація, A/B тести (post-MVP)

## Критерії приймання

1. Guest може переглянути Landing, Catalog, Course Preview без авторизації
2. Форма звернення валідує email в реальному часі; не відправляється без обох чекбоксів або з невалідним email
3. При відмові від Art.9 чекбоксу — Care Case створюється без теми/опису, людина бачить попередження
4. Після відправки форми — екран підтвердження з очікуваним часом відповіді
5. "Почати курс" на превью відкриває модальне вікно згоди → OAuth → перший урок
6. При помилці OAuth після надання згоди — rollback: дані згоди видаляються, enrollment не створюється
7. Responsive layout (mobile-first), LCP < 2 секунди
8. Навбар: Логотип, Курси, Увійти — відповідає site-map
