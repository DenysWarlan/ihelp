# E12 -- GDPR та захист персональних даних

## Мета

Забезпечити повну вiдповiднiсть платформи вимогам GDPR: збiр та управлiння згодами, право на видалення та експорт даних, retention policy, захист вiд витоку PII -- з урахуванням специфiки кризових кейсiв.

## Скоуп

### Входить (MVP)

- **AUTH-7**: Два чекбокси згоди (загальна + Art.9 чутливi данi), зберiгання timestamps, логiка вiдкликання згоди з урахуванням активних/кризових кейсiв
- **Art.17 (право на видалення)**: каскадне видалення персональних даних протягом 30 днiв, анонiмiзацiя кейсiв для статистики, блокування видалення при кризовому кейсi (EDGE-63, EDGE-65)
- **Art.20 (портабельнiсть)**: експорт даних Person у ZIP (JSON + файли), без приватних нотаток консультанта (EDGE-64)
- **Art.15 (SAR)**: автоматичне розпiзнавання запитiв на доступ до даних у чатi, маршрутизацiя до DPO/адмiна (EDGE-64a)
- **Взаємний lock**: експорт та анонiмiзацiя не можуть виконуватись одночасно для одного Person
- **Watermarking**: маркери в експортованих даних (анонiмiзованi для Person, повнi для Staff)
- **PII-фiльтрацiя**: сканування приватних нотаток на наявнiсть PII iншого Person з попередженням
- **Retention policy**: правила зберiгання переписок, повiдомлення за 30 днiв до видалення
- **Логування доступу**: всi дiї з персональними даними (хто, коли, що)
- **Принцип чотирьох очей**: доступ адмiна до переписок потребує затвердження

### Не входить

- Iнтеграцiя з зовнiшнiм DPO-iнструментом
- Cookie consent banner (окремий фронтенд-тiкет)
- DPIA документ (юридичний процес, не технiчний)

## Критерiї приймання

1. Person при першому входi бачить два окремi чекбокси згоди; без обох -- flow не продовжується
2. Person може вiдкликати згоду Art.9 -- чутливi поля анонiмiзуються, консультант отримує сповiщення, кейс продовжується в обмеженому режимi
3. Person може запросити видалення -- данi видаляються протягом 30 днiв, кейси анонiмiзуються для статистики
4. При кризовому кейсi видалення та вiдкликання згоди вiдкладаються з повiдомленням Person
5. Експорт даних генерує ZIP з JSON + файлами; приватнi нотатки консультанта виключенi; watermark -- тiльки Person ID + timestamp
6. SAR-фрази у чатi автоматично маршрутизуються до DPO/адмiна з пiдтвердженням Person
7. Всi дiї з персональними даними логуються в audit log
