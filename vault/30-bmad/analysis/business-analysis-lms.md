# Бізнес-аналіз модуля LMS — "Є турбота"

> Цей документ деталізує бізнес-процеси підсистеми курсів (LMS). Загальний бізнес-аналіз платформи — див. [business-analysis.md](business-analysis.md).

## 1. Призначення модуля

Модуль курсів (LMS) — це self-help інструмент для Person, який доповнює роботу з консультантом. Курси не замінюють живу допомогу, а дають структуровані матеріали для самостійного опрацювання між сесіями.

**Ключове обмеження:** курси — безкоштовні. Монетизація курсів суперечить місії проекту (див. PRD §9 "Rejected Features").

## 2. Ролі та їхня взаємодія з LMS

| Роль | Дії з курсами |
|------|---------------|
| **Person** | Переглядає каталог, записується на курс, проходить уроки, відстежує прогрес, натискає "Мені важко", скидає прогрес, проходить кілька курсів одночасно |
| **Consultant** | Бачить прогрес Person по курсу в картці кейсу, рекомендує курс Person (v1.1), адаптує розмову до контексту уроку |
| **Coordinator** | Бачить аналітику: курсів розпочато/завершено, конверсію "курс → звернення" |
| **Admin** | Створює, редагує, публікує, приховує, архівує курси. Управляє контентом уроків. Імпортує/експортує курси |
| **Supervisor** | Немає прямої взаємодії з LMS |

## 3. Структура контенту

### 3.1. Ієрархія

```
Курс (Course)
├── Метадані: назва, опис, обкладинка, мова, теми (tags)
├── Налаштування: trigger warnings per-lesson, рекомендований порядок
└── Уроки (Lesson[]) — впорядковані за sortOrder
    ├── Текстовий контент (rich text)
    ├── Відео (embed YouTube/Vimeo)
    ├── Файли-матеріали (PDF, аудіо)
    └── Тести / запитання (v1.2)
```

### 3.2. Типи уроків

| Тип | Опис | MVP |
|-----|------|-----|
| `text` | Rich text з форматуванням | ✅ |
| `video` | Embed YouTube/Vimeo + текстовий супровід | ✅ |
| `mixed` | Комбінація тексту, відео, файлів | ✅ |
| `quiz` | Тестові запитання після уроку | v1.2 |

### 3.3. Trigger warnings

Уроки, що торкаються чутливих тем (суїцид, насильство, втрата), мають:
- Позначку `hasTriggerWarning: true` на рівні уроку
- Банер перед контентом: "Цей урок містить чутливі теми"
- Кнопку "Пропустити" для обходу уроку
- Кнопку "Мені зараз важко" — створює або оновлює кейс

## 4. Життєвий цикл курсу

```
  draft ──→ published ──→ hidden ──→ archived
    ↑           │            ↑ │
    └───────────┘            │ │
    ↑   (unpublish)          │ └──→ (soft delete)
    └────────────────────────┘
              (revert to draft)
```

| Стан | Видимість у каталозі | Enrolled users | Дії Admin |
|------|---------------------|----------------|-----------|
| `draft` | ❌ Невидимий | — | Редагування, публікація |
| `published` | ✅ Видимий | Можуть проходити | Редагування, приховання |
| `hidden` | ❌ Невидимий | Бачать "курс призупинено", прогрес зберігається | Публікація, архівування |
| `hidden` → `draft` | — | — | Повернення в чернетку для переробки (enrolled users зберігають прогрес зі статусом "курс призупинено") |
| `archived` | ❌ Невидимий | Бачать "курс завершено/архівовано", прогрес зберігається | Видалення (soft) |

**Edge case:** Курс архівовано, а enrolled Person має active case з `sourceCourseId` → система сповіщує консультанта про архівацію, оновлює контекст кейсу.

## 5. Процеси

### 5.1. Створення курсу (Admin)

1. Admin натискає "Новий курс" → форма з полями: назва, опис, мова, теги
2. Курс створюється зі статусом `draft`
3. Admin додає уроки: текст, відео (embed URL), файли
4. Admin позначає уроки з trigger warnings
5. Admin натискає "Опублікувати" → курс з'являється в каталозі
6. **Валідація перед публікацією:** мінімум 1 урок, назва, опис заповнені

### 5.2. Імпорт курсу (Admin) — НОВА ФУНКЦІЯ

**Мета:** спростити додавання курсів, дозволити обмін контентом між інстансами платформи.

**Формат:** JSON bundle

```json
{
  "version": "1.0",
  "course": {
    "title": "Подолання тривожності",
    "description": "8-тижневий курс...",
    "language": "uk",
    "tags": ["тривожність", "self-help"]
  },
  "lessons": [
    {
      "sortOrder": 1,
      "title": "Що таке тривожність?",
      "type": "text",
      "content": "# Урок 1\n\nТривожність — це...",
      "hasTriggerWarning": false,
      "attachments": ["files/lesson-1-worksheet.pdf"]
    }
  ],
  "files": {
    "files/lesson-1-worksheet.pdf": "<base64 або URL>"
  }
}
```

**Процес імпорту:**
1. Admin завантажує JSON файл
2. Система валідує структуру та обов'язкові поля
3. Курс створюється зі статусом `draft` (ніколи не `published` автоматично)
4. Файли завантажуються в S3 `courses/{courseId}/`
5. Admin переглядає результат і публікує вручну

**Обмеження:**
- Максимальний розмір JSON bundle: 50 MB (включаючи base64-encoded файли)
- Максимальний розмір окремого файлу-вкладення: 10 MB
- Підтримувані формати файлів: PDF, MP3, MP4
- Відео тільки як embed URL (YouTube/Vimeo), не як файл
- Санітизація HTML/rich text контенту при імпорті (захист від XSS/script injection)
- Дублікати: імпорт завжди створює новий курс, навіть якщо title збігається

### 5.3. Експорт курсу (Admin)

1. Admin натискає "Експорт" на картці курсу
2. Система генерує JSON bundle з контентом усіх уроків та файлами
3. Файл завантажується через браузер
4. **Що НЕ експортується:** enrollments, прогрес, статистика

### 5.4. Запис на курс (Person)

1. Person переглядає каталог → обирає курс → натискає "Записатися"
2. **Guard:** запис дозволений тільки на курси зі статусом `published`. Draft/hidden/archived → 404 або "Курс недоступний"
3. Створюється `Enrollment` (person + course, unique constraint)
4. Person бачить курс у "Мої курси" в кабінеті
5. **Edge case:** спроба подвійного запису → 409 Conflict
6. **Edge case:** Person хоче два курси одночасно → дозволено, окремий прогрес

### 5.4a. Відписка від курсу (Person)

1. Person натискає "Покинути курс" на сторінці курсу
2. Діалог підтвердження: "Прогрес буде збережено в історії. Продовжити?"
3. Enrollment переходить у статус `dropped`. Прогрес зберігається для аналітики
4. Person може повторно записатися — створюється новий Enrollment

### 5.5. Проходження курсу (Person)

1. Person відкриває урок → читає/дивиться контент
2. Натискає "Урок пройдено" → `LessonProgress` записується
3. Progress bar оновлюється: `completed_lessons / total_lessons * 100%`. Guard: якщо `total_lessons = 0` (всі уроки видалено) → progress = 0%, не ділити на нуль
4. Після завершення всіх уроків — курс позначається як пройдений
5. **При додаванні нового уроку до опублікованого курсу:** прогрес enrolled users автоматично перераховується (total_lessons збільшується → % зменшується). Person отримує in-app повідомлення "Додано новий урок"

**На кожному уроці доступні:**
- Кнопка "Мені зараз важко" (червона, з іконкою серця)
- Trigger warning банер (якщо урок позначений)
- Навігація між уроками (попередній/наступний)

### 5.6. Кнопка "Мені важко" — інтеграція з кейсами

| Ситуація | Поведінка |
|----------|-----------|
| Person **має** активний кейс | Повідомлення з контекстом (курс, урок) надсилається поточному консультанту. Person перенаправляється в існуючий чат |
| Person **не має** активного кейсу | Створюється новий `CareCase` з `source: "course_trigger"`, `sourceCourseId`, `sourceLessonId`. Автоматичне призначення duty consultant |
| Person натискає кнопку **повторно** за короткий час | Debounce на клієнті (3 сек) + idempotency check на сервері: якщо case створено < 1 хв тому з тим же sourceLessonId → повернути існуючий |
| **Жоден** duty consultant недоступний | Кейс створюється без консультанта, потрапляє в чергу координатора. Person отримує: "Ваше звернення зареєстровано, з вами зв'яжуться найближчим часом" |

### 5.7. Скидання прогресу (Person)

1. Person натискає "Скинути прогрес" на сторінці курсу
2. **Діалог підтвердження:** "Весь прогрес буде скинуто. Попередній результат збережеться в історії. Продовжити?"
3. Попередній результат зберігається в історії
4. Прогрес обнуляється, Person може пройти курс заново
5. **Ліміт:** максимум 3 скидання на курс (захист від зловживання / bot-like поведінки)

### 5.8. Рекомендація курсу (Consultant → Person) — v1.1

1. Консультант в картці кейсу бачить прогрес Person по курсах
2. Може рекомендувати курс (пропозиція, не примус)
3. Person отримує сповіщення з рекомендацією
4. Person може прийняти або відхилити + залишити feedback чому не підходить
5. **Обмеження:** автоматичне зарахування заборонене без явної згоди Person
6. **Guard:** рекомендувати можна тільки `published` курси. Hidden/archived → помилка "Курс недоступний для рекомендації"

## 6. Аналітика курсів

### 6.1. Метрики (Coordinator / Admin)

| Метрика | Формула | Ціль |
|---------|---------|------|
| Кількість записів | COUNT(Enrollments) per course | Популярність |
| % завершення | Enrollments(completed) / Enrollments(total) | > 30% |
| Конверсія курс → звернення | Cases(source=course_trigger) / Enrollments | > 20% |
| Середній час проходження | AVG(completedAt - enrolledAt) | Для планування |
| Drop-off по урокам | Останній пройдений урок per enrollment | Оптимізація контенту |

### 6.2. Дані для консультанта

В картці кейсу консультант бачить:
- Які курси проходить Person
- Прогрес по кожному курсу (progress bar)
- На якому уроці зупинився
- Чи натискав "Мені важко" (і на якому уроці)

## 7. Edge cases

| # | Ситуація | Рішення |
|---|----------|---------|
| 1 | Person проходить курс і має кейс одночасно | Незалежні сутності. Консультант бачить прогрес курсу в картці |
| 2 | Контент уроку тригерить Person | Disclaimer + кнопка "Мені важко" + можливість пропуску |
| 3 | Person хоче пройти курс заново | Скидання прогресу, попередній результат у історії |
| 4 | Два курси одночасно | Дозволено. Окремий прогрес для кожного |
| 5 | Курс видалено адміном під час проходження | Soft delete → "Курс архівовано". Прогрес зберігається |
| 6 | Курс архівовано + active case з sourceCourseId | Notify консультанта. Оновити case context |
| 7 | Distress з курсу без активного кейсу | Auto-create case з source=course_trigger |
| 8 | Імпорт курсу з некоректним JSON | Валідація → повідомлення про помилки |
| 9 | Імпорт курсу з файлами > 50 MB | Відхилити з повідомленням про ліміт |
| 10 | Експорт курсу з великою кількістю медіа | Асинхронна генерація, сповіщення коли готово |
| 11 | Person з GDPR-запитом на видалення | Каскадне видалення: enrollments, progress. Курс залишається |
| 12 | Публікація курсу без жодного уроку | Блокувати: валідація мін. 1 урок |
| 13 | Редагування опублікованого курсу | Версіонування контенту (PRD LMS-7): enrolled users бачать версію на момент enrollment. Адмін може примусово оновити всіх з повідомленням. Маппінг old→new lesson ID при реструктуризації |
| 14 | Видалення уроку з опублікованого курсу | Перерахувати прогрес enrolled users. Посилання в кейсах → "(урок видалено у новій версії)" |
| 15 | Enrollment на non-published курс | Блокувати: запис тільки на `published`. Draft/hidden/archived → "Курс недоступний" |
| 16 | Admin додає урок до опублікованого курсу | Перерахувати % прогресу enrolled users. In-app повідомлення "Додано новий урок" |
| 17 | Person натискає "Мені важко" повторно за секунди | Debounce 3 сек (клієнт) + idempotency (сервер): не створювати дублікат кейсу |
| 18 | Жоден consultant недоступний при "Мені важко" | Кейс без консультанта → черга координатора. Person отримує підтвердження |
| 19 | Admin reorders уроки під час проходження Person | Прогрес прив'язаний до lesson ID, не sortOrder. Зміна порядку не впливає на completed lessons |
| 20 | Імпорт JSON з XSS/script injection в content | Санітизація HTML при імпорті. Видалення `<script>`, `on*` атрибутів |
